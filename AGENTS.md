# GreenLens development contract

Implement only the bounded v0.1 release in `docs/v0.1-spec.md`. This is an international, local-first, offline-capable open-source scientific application. Rust owns geometry, validation, units, hashes, statistics and comparison rules. CLI and Tauri desktop use the same Rust application services. Never fabricate simulation results or count mocks as engine/native acceptance.

Use native Windows, Rust/MSVC, Tauri 2, React/TypeScript/Three.js WebGL2, npm lockfile and direct argument-array Radiance subprocesses. No Python runtime is required. No arbitrary shell frontend commands, shell scene directives, mandatory network/cloud, database or dynamic plugin ABI. Keep simulation adapters, data providers and assessment consumers distinct.

Preserve existing work. Source stays in the chosen checkout. Build and active run caches belong under `%LOCALAPPDATA%/GreenLens`; engines are installed separately outside synced source. Never commit credentials, personal configuration, machine paths, downloaded engines, large outputs or build products. Use synthetic or licensed data. Inspect staged changes before public commits. Do not force-push unrelated history.

Original code is Apache-2.0. Review actual dependencies and bundled binary licenses; retain notices. Scientific claims must identify assumptions and evidence. Adapter agreement is integration verification, analytical fixtures establish limited behavior, metrics are not certification. No BEAM or other regional rules in the universal core.

Track implemented, verified, unverified and blocked acceptance separately in `docs/progress.md`. Run required real-engine tests with explicit failure if unavailable. Preserve thresholds; investigate failures rather than weaken them. Mark the release complete only when gates 0–3 have evidence, including installed native desktop verification. Keep later roadmap features out of scope. Record blocker remedies and smallest intervention; continue independent useful work.

Use clear file ownership for parallel agents. Inspect current files before edits. Maintain reproducible scripts, versioned JSON and portable relative paths. Validate integrity and paths before reading/replaying exports; never execute commands from packages. Require full successful process completion, finite output and exact sensor count before finalizing runs. Cancellation and shutdown must terminate the Windows process tree.
