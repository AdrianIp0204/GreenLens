# Architecture

The active v0.3 extension introduces versioned static/hour/annual studies, a local EPW data provider, separate physical/metric identities and bounded chunked annual results. See `v0.3-spec.md` and `v0.3-scientific-method.md`; release verification remains incomplete. Legacy model/run codecs and engine identity remain separately dispatched without rewriting old evidence. Frontend requests bounded result slices and Rust-derived metrics rather than full matrices or local physics.

The Rust core defines versioned inputs, authoritative geometry, sensor generation, scientific conversion, hashes, statistics and compatibility. The Radiance adapter produces bounded engine inputs and invokes the pinned executables. The runner/application service coordinates one job, process supervision, persistence, comparison, evidence export and replay. CLI and Tauri commands call the same service; React/Three.js only renders validated geometry/results and issues typed bounded requests.

Simulation adapters produce evidence. Data providers supply validated inputs with source rights. Assessment modules can consume evidence but do not define simulation physics. Only the Radiance adapter and synthetic input data exist in v0.1; the latter two categories are architectural boundaries, not a marketplace or dynamic ABI.

Durable project data is relative, JSON/text and checksummed. Active jobs and octrees live in per-user local cache. Finalization validates before promotion and manifest update. Historical runs preserve their input snapshots; current inputs determine staleness. Packages never supply executable commands. Native cancellation/shutdown supervises the entire process tree.

## v0.2 document and workspace boundaries

`workspace/useDocument.ts` coordinates the native application service, pending evidence, project revisions and destructive-action protection. `DocumentHistory` stores complete before/after input snapshots only after a successful Rust validation. Commands, Properties and viewport handles call that same accepted-edit path. A provisional drag lives inside the viewport until commit; Escape drops it. Failed validation cannot advance either history stack. Save updates the persistence baseline without resetting history; another document or explicit disk reconciliation resets it.

`ViewportEngine` owns one WebGL renderer and four persistent camera objects for the lifetime of `SceneView`. Its scientific-to-renderer transform is explicit. Validated input changes replace affected rendered geometry resources; selection, colors and layers update display state. Framing happens on new-document initialization or an explicit navigation command. Selection uses semantic IDs, not triangle IDs. Preview/snapping math is interaction geometry; Rust remains authoritative for final validation, geometry, hashes and saved simulation inputs.

Scientific document, viewport display, selection and simulation state are separate. The optional `greenlens.display.v0.2` extension contains cameras, layers, object display overrides and modeling aids. It is excluded from scientific hashes/history. The base project schema remains 0.1.0 so v0.2 reads existing v0.1 projects; older applications may reject a project after display state has been added. Immutable run schemas and bytes remain untouched. See [persistence](persistence.md) for revision conflicts, full-copy promotion and bounded export.

Build provenance is generated by Cargo from the actual checkout at build time, with explicit verifiable CI assertions. See [build provenance](build-provenance.md). No source identity is cached in the development shell.

## v0.3 application services

`greenlens-core::weather` validates the original EPW and produces a versioned normalized input/time axis. `greenlens-core::study` owns study validation, physical/metric identity and streaming weighted metric arithmetic. The provider has no engine dependency. `greenlens-radiance::annual` owns recognized versioned transport recipes, finite solar-disc visibility and monitored subprocesses; selected-hour and annual modes share that implementation. Historical methods retain their own exact profiles and generated process sequences. The provisional repeated-coefficient method keeps its scaled receiver separate from the unit receiver used for direct transmission.

The runner's `weather`, `studies`, `climate`, `timeseries` and `climate_export` modules expose portable import, study transactions, immutable evidence, bounded queries and recognized replay. `climate_job` uses the same one-active-job supervisor, cancellation, pending-evidence protection and manifest promotion as static runs. Expensive Tauri operations run on blocking workers so result loading does not block the UI event loop. One hourly vector or one sensor series crosses IPC; complete matrices remain in bounded files.

Document history distinguishes model transactions from study transactions. Rust validates both. Undo restores only the edited alternative's model/study, retaining runs and weather added later. Restoring an initially absent legacy climate extension removes it only if no later climate evidence or other study requires it. Saving does not clear history. Physical-result lookup selects the newest compatible immutable snapshot; changed metric settings request newly identified derived values rather than changing that snapshot.
