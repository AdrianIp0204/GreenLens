# Native Windows workspace captures

These are unaltered application-window screenshots from installed GreenLens 0.2.0, without a development server. They show synthetic models and contain no private paths. The physical display was 1920×1080 with 125% Windows scaling. Capture tooling returns display-scaled pixels; the application's Diagnostics measurements distinguish native client size from CSS size.

The captures contain JPEG bytes. Their public `.jpg` extensions match that format; renaming the earlier `.png` filenames did not change any image bytes. Original local evidence filenames are retained as recorded in the native verification log.

- `selection-workspace-candidate05.jpg`: installed candidate 05, clean build `1fbb654`, with Add active and Window plus Room envelope selected. The unaltered 1442×864 capture shows the always-visible count/names and named Objects list. It establishes the observed selection state, not an unperformed keyboard-modifier gesture. Current package hashes are in `../../v0.2-release-artifacts.json`.
- `compact-selection-candidate05.jpg`: the same installed candidate with the selection strip, expanded command history, sensor drawer and Properties panel visible. The measured native client is 1125×625 pixels, CSS client 900×500, DPR 1.25. There is no calculated result displayed in this capture; the sensor table's empty lux cells do not represent simulation values. This tests a compact window on the same 1920×1080 monitor, without changing global display settings.
- `repaired-workspace-candidate04.jpg`: installed candidate 04, clean build `c6feb7b`, four Shaded views with Window selected and Move active. This unaltered 1442×864 capture shows the fresh saved fixture prepared for human retest after the source repair, with center X 2 m, sill 0.9 m and Undo disabled. It is not proof that the pending gestures passed. Its package hashes are preserved in `../../v0.2-candidate04-artifacts.json`.
- `four-view-window-editing.jpg`: installed candidate 03, clean build `bb0456c`, four views, selected window and constrained Move handles. Actual source and package hashes are in `../../v0.2-candidate03-artifacts.json`. This is the saved, idle document prepared for manual gesture observations; the user subsequently reported modifier-selection and held-drag Escape failures. A screenshot does not establish that those gestures passed.
- `native-ab-comparison.jpg`: earlier installed candidate, actual real Radiance A/B results and shared lux scale. Native client 1920×991; CSS client 1536×794; DPR 1.25. The run snapshots retain actual `b7b8d32` dirty-build provenance. Candidate 03 CLI (`bb0456c`) replay passed both runs with zero maximum lux difference; this is not a candidate 04 A/B screenshot.
- `compact-workspace.jpg`: corrected compact layout in that earlier installed candidate, with command history, result drawer and Analysis panel visible. Native client 1125×625; CSS client 900×500; DPR 1.25. This smaller-than-1366×768 usable window is evidence for the compact layout; it is not a claim that the physical monitor resolution was changed to 1366×768.
