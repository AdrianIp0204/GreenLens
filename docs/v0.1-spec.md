# GreenLens v0.1 release contract

## Purpose and scope
An international, local-first, open-source building environmental simulation and analysis platform for architects, environmental-design consultants, researchers and students. Reuse established scientific engines; Rust is preferred for core/performance work. Normal calculation requires no network, subscription, cloud or paid AI. Initial dependency acquisition can use internet. Windows is primary; WSL-only success is insufficient.

The exact calculation label is **Static daylight illuminance under a prescribed CIE standard overcast sky.** This is not annual daylight, measured weather, a selected-date prediction or certification compliance.

Excluded: annual daylight, energy, IFC, certification scoring, CFD, full BIM editing, optimization, remote execution and plugin marketplace. Hong Kong may appear only as optional example metadata; BEAM Plus is roadmap-only.

## Architecture
Rust Cargo workspace: `crates/greenlens-core`, `greenlens-runner`, `greenlens-radiance`, `greenlens-cli`; `apps/desktop`, `schemas`, `examples`, `tests/fixtures`, `scripts`, `docs`. Shared domain/application services serve CLI and Tauri 2 desktop (React, TypeScript, Three.js WebGL2, npm lockfile). Direct Rust-managed Radiance processes; no required Python runtime or database. Versioned JSON contracts, JSON/CSV results. Apache-2.0 original code and reviewed dependency inventory/notices. Separate simulation adapter, data-provider and assessment-module interfaces; implement only Radiance and release data, no dynamic ABI/distributed platform.

Rust authoritatively owns geometry, units, validation, hashes, scientific conversion, statistics and comparisons. Frontend only displays validated data and requests bounded actions. CLI covers doctor, validate, run, compare, export, replay.

## Model, coordinates and editing
One rectangular room, one rectangular window in a defined facade, optional horizontal overhang, one detached opaque rectangular surrounding obstruction, neutral diffuse reflectances and one neutral zero-thickness Radiance glass pane. Support bounded editing of all room/window dimensions, glazing, reflectances, overhang, obstruction and sensor settings; actionable rejected inputs. Maximum 10,000 sensors.

Synthetic default: room 4 m wide × 6 m deep × 3 m high; centered window 1.8 m × 1.5 m, sill 0.9 m; normal-incidence visible transmittance 0.60; ceiling/walls/floor reflectances 0.80/0.50/0.20; prescribed exterior horizontal illuminance 10,000 lx; ground reflectance 0.20; horizontal workplane 0.80 m; requested maximum grid spacing 0.50 m; wall inset 0.25 m. Alternative A has no overhang; B has 0.60 m projection. Document all other defaults.

Metres internally, right-handed +X east/+Y north/+Z up, azimuth clockwise from true north. Document model-local/world transform and explicit renderer transform. Window at y=0 faces south at zero model rotation; fix in tests. Split facade around aperture; no opaque surface across glass. Validate finite dimensions, window containment, winding, nondegenerate polygons, overlaps, obstruction clearance and sensor containment.

Tile inset rectangle with equal-area cells; derive/report actual spacing from requested maximum. Stable sensor IDs, positions, upward directions and order; centers of cells. Optional location/IANA timezone metadata. Sky is azimuth-symmetric; no simulated date or annual sequence. UTC run timestamps; no apparent weather/date/occupancy controls.

## Engine and scientific conventions
Initially evaluate official LBNL-ETA/Radiance 6.0.2 tag `rad6R0P2`, Windows asset `Radiance_c1700d56_Windows.zip`, proposed SHA-256 `c4f02efcb4a33f4a43b7ce0ba58100544abc317a1be61f7b0425a64a66eb8a09`. Reverify upstream asset/digest, pin tested artifact in manifest, inspect archive/license/libraries/runtime requirements. Separate versioned per-user installation outside OneDrive; no engine binary export by default. Do not replace with rolling HEAD without documented reason.

For refractive index 1.52 and T in [0.01,0.90]:
`tn = (sqrt(0.8402528435 + 0.0072522239*T*T) - 0.9166530661)/(0.0036261119*T)`.
Require finite tn in [0,1], never clamp; identical RGB values on one glass surface. Explain equivalent single-pane limits.

Investigated sky command: `gensky -ang 45 0 -c -B (E_out/179) -g ground_reflectance`; verify pinned source/docs. Append explicit neutral upper-sky and lower-ground hemisphere definitions. Angular argument is an implementation convention, not simulated solar conditions. Compile with oconv. Use rtrace -I+, explicit ASCII RGB, one worker, explicit numerical settings, no reused ambient cache. Lux = `179*(0.265074126*R + 0.670114631*G + 0.064811243*B)`, verified against pinned source. This is not broadband solar W/m² conversion. Argument arrays and binary-safe streams; no shell interpolation/embedded commands. Engine library environment applies only to children.

## Jobs, provenance and comparison
One active job. States: queued, preparing, running, completed, failed, cancelled. Supervise entire Windows process tree and terminate on cancel/shutdown. Partial runs never complete. Completion requires successful required exits, exact sensor count/order, finite valid output, units and complete provenance.

Historical run inputs are immutable. Staleness relates historical result to current inputs; never silently place old data on edited geometry. Record app/schema/adapter/engine versions and source commit when available, executable/library hashes, normalized input/sensor hashes, exact numeric settings/arguments, necessary child environment, generated inputs, raw output, processed data, logs/exits and UTC times. Do not include whole environment, credentials or personal absolute paths. Machine configuration separate from replay recipe.

A/B requires identical room/world sensor definitions, environment/obstruction, sky, engine and numerical settings. Allow documented window/glazing/overhang changes. Separate comparison-condition/full run fingerprints; reject incompatibility without resampling. Shared heatmap scale, sensor absolute deltas and min/mean/max stats. Omit percentage deltas or explicitly undefined near zero. Reflective shading need not decrease every sensor.

## Desktop
Create/open example or saved project; edit bounded inputs with units/actionable validation; inspect all geometry and sensors; run actual engine with states/logs; lux heatmap/legend/sensor values/table fallback; create/run alternative and compare; save/reopen/export evidence. Legibility and scientific traceability first. No fabricated results in delivered workflow; explicit test mocks do not prove real execution.

## Acceptance gates
### 0: native engine feasibility (before substantial UI)
Establish Rust/MSVC/frontend toolchains. Acquire/verify native pinned Radiance. Execute gensky, oconv, rtrace with library lookup, diagnose DLL/path failures, exercise spaces/non-ASCII paths, record actual versions/licenses/commands and real finite outputs. Downloads/version text alone do not pass. Document exact blocker/remedies/minimum intervention if native remains blocked.

### 1: reproducible headless science
Implement core/adapter/runner/CLI/persistence/export. All thresholds below are required, never presumed achieved:
A. Adapter/export replay vs direct same-engine/settings: each sensor within max(0.1 lx, 0.1% reference); integration verification, not independent physical validation.
B. Uniform luminous hemisphere independently matches E=pi*L within 1%.
C. Unobstructed prescribed overcast horizontal sensor matches exterior illuminance within 1%.
D. Sealed black enclosure below 0.1 lx.
E. Independent aperture fixture: black room, unglazed rectangular aperture, black ground, five interior horizontal sensors. Independently integrate `E=integral_A Lsky(omega)*max(0,n_sensor dot omega)*abs(n_window dot omega)/r² dA`; upper sky `Lsky=Lz*(1+2*omega_z)/3`, `Lz=9*E_out/(7*pi)`; lower hemisphere zero. Quadrature convergence <0.1%, each Radiance sensor within max(0.5 lx,3% reference).
F. Shipping room profile vs higher sampling/bounce depth: mean difference <=2%, each sensor within max(2 lx,5% reference). Investigate, freeze/record profiles.
Test geometry rejection, transforms, glazing, intensity scaling, appropriate symmetry, malformed/truncated output, nonzero exits, missing engine, cancellation and staleness. No byte-identical stochastic or general measured-building validation claims.

### 2: complete native desktop
Actual Windows desktop through Rust/Radiance: A/B edit/run/compare/save/reopen/export; units/shared scale/sensor identity/table checked. Visible invalid input, missing engine, failed, cancelled and stale states verified. Browser-only/mock checks insufficient. Copy saved A/B project elsewhere, make original scratch unavailable, reopen unchanged arrays/provenance and export. Replay exported evidence through CLI at A tolerance. Cancellation kills process tree and creates no completed result.

### 3: package, document, verify
Build per-user Windows package (prefer NSIS) and CLI. Explicit WebView2/separate engine requirements. Installed package without dev server performs actual run/save/export. Unsigned is acceptable with no signing/reputation claims. Clean-machine route and actual tested environment distinguished. Synthetic example, install/launch/method/validation/limitations/replay docs. Native Windows CI: fmt/clippy/tests, TS, frontend build/tests, CLI integration, required actual-engine suite, production desktop build. Prefer native UI automation; otherwise reproducible native verification evidence. Unavailable engine means explicit required-test failure; optional skips do not satisfy acceptance.

## Licensing and claims
Versioned inventory includes code/binaries/bundled libraries/datasets with sources, actual versions/digests/licenses/notices/modifications/redistribution obligations; subprocess separation does not settle licensing. Inspect Radiance selected package. Tauri/Three code permissive licenses differ from branding terms. No Honeybee (AGPL), IfcOpenShell (LGPL/GPL), EnergyPlus or OpenStudio runtime needed. Weather source rights are distinct from EPW format. No copied proprietary standards/manuals/datasets.

Metric != criterion evaluation != formal certification. Analytical fixtures and adapter verification are limited evidence. Simplified sky/glazing/geometry constrain interpretation. Future BEAM module must independently audit then-current amendments/applicability/standards/evidence (planning reference: NB v2.0 2025 and Circular 2025.222, effective 2025-12-01, annual daylight requirement); no thresholds/compliance labels in v0.1.

Logical inspected commits and authorized repository setup/push, no unrelated history overwrite. Reverify authenticated account and preferred GreenLens repository immediately before creation; inspect any existing repo ownership. Report implementation, exact install/launch/CLI commands, numerical evidence, artifact paths, limitations/blockers, Git state/repository URL and remaining intervention. Release incomplete until every required acceptance item has evidence. Stop at v0.1.
