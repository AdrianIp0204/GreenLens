# GreenLens v0.2 release contract

## Purpose and scope

Deliver a viewport-dominant native Windows modeling workspace inspired by Rhino 8 interactions, within GreenLens's existing analytical model. This explicitly extends the historical v0.1-only development scope. Retain Rust/MSVC, Tauri 2, React/TypeScript, Three.js WebGL2, npm lockfile, shared CLI/application services and direct Rust-managed Radiance execution. Original GreenLens assets and implementation only; official McNeel documentation is behavioral reference, not code/assets to copy. Rhino installation is never required.

The scientific model remains one rectangular room, one rectangular window, optional horizontal overhang and one optional detached rectangular obstruction. Exact calculation label: **Static daylight illuminance under a prescribed CIE standard overcast sky.** All v0.1 numerical conventions, profiles and thresholds remain unchanged. No NURBS/Brep/freeform solids/booleans/3DM/DWG/Grasshopper/BIM, annual daylight, energy or certification. Record prerequisites for those future categories in the roadmap only.

## Phase 1: document correctness

1. Reconfirm and fix unguarded New/Open replacement. Save / Discard / Cancel protects New, Open and native close; failed/cancelled Save blocks the requested destructive action. Integrate cancellation/wait for active jobs and pending completed evidence. Text fields retain native editing behavior.
2. Recover completed evidence after external project revision changes during a run. Explicit reload/reconcile must preserve external changes and the immutable completed snapshot, or a complete copy can be saved to a new directory. Never overwrite a stale revision silently; never discard run files/checksums. Regression covers an external revision change during an actual or explicitly synthetic completed run lifecycle.
3. Keep renderer, controls and cameras alive across selection, cutaway, validated inputs, display/result arrival and tab/panel changes. Update scene objects/colors/markers incrementally. Frame only a new document or explicit command. Dispose removed graphics resources.
4. Establish build-time source commit/dirty identity and rebuild tracking. Reusing a shell after edits or commits cannot create stale identity/false clean. Intentional CI overrides must be explicit and checked. Test clean, modified and changed-commit builds in disposable repositories without rewriting project history.
5. Share archive writer/reader entry and uncompressed-size limits. Reject impossible exports before writing with actionable guidance or support selected runs/pairs. Avoid unbounded A×B comparisons. Every successful export must satisfy its own structural reader limits. Use synthetic boundary fixtures rather than costly simulation batches.

## Workspace and views

Compact top menus/toolbars; command entry with expandable history near top; narrow left modeling strip; central viewport area; resizable/collapsible right Properties/Layers/Analysis; bottom coordinates/metres/modeling-aid/job status. Comparison, sensor table, logs, evidence, method and export remain accessible. Native Open, Save As and Export dialogs support ordinary operation without typing paths. Every visible action works or explains its current unavailability. Layout must work at 1366×768 and 1920×1080, including tested Windows scaling.

Perspective plus Top/Front/Right orthographic views; four-view and maximized layouts; active highlighting; double-click title maximize/restore. Wheel zoom. Perspective right-button drag orbits; Shift+right-button pans. Orthographic right-button drag pans and never changes projection. Document modifiers. Zoom Extents and Zoom Selected. Wireframe/Shaded/Analysis modes. Preserve every camera and target across all ordinary document/display/selection/result changes and layout switches. Keep scientific Z-up to renderer `[x,z,-y]` conversion. Document view directions/grid axes.

## Selection, properties and semantic identities

Stable semantic IDs represent the room envelope and inspectable generated surfaces, window, overhang, obstruction, sensor plane and individual sensors. Triangles are not independent editable CAD objects. Click/hover, Shift-add, Ctrl-remove; left-to-right contained window selection and right-to-left crossing selection; Escape cancel/deselect; synchronized object/layer list, viewport and Properties. Hidden objects cannot be selected; locks prevent edits without removing simulation geometry. Provide overlapping-object disambiguation. Properties show actual supported parameters, units and constraints. Mixed selections cannot silently apply ambiguous transforms.

## Constrained editing and transactions

Window moves in its facade plane and resizes width/height. Overhang edits projection/side extension/gap. Obstruction edits lateral position/facade distance and width/depth/height. Room edits dimensions and vertical-axis rotation. Create/remove optional overhang/obstruction. Room/window are required; no arbitrary translation/rotation/duplication/deletion beyond the analytical schema. Provide Gumball-style supported handles and numeric entry; explain unsupported operations.

A drag begins a provisional transaction, previews responsively, validates its final candidate in Rust, commits one accepted document edit, and creates exactly one undo entry. Escape restores the original model. Rejected commits restore the last valid model and report actionable validation. No renderer-only geometry can appear as a saved/simulated change. Menus, shortcuts, commands, properties and gizmos share the same application action/transaction path.

Undo/redo restores whole edits including optional creation/removal; new edits clear redo; cancelled/invalid operations create no accepted entries; returning to exact prior scientific input restores result-validity relationships. Display/camera changes never enter scientific history; Save retains history; opening another document resets it deliberately. True Save As copies all referenced compact immutable evidence. Separate document, view, selection and simulation state. Refactor cohesive modules instead of growing monolithic components.

## Commands, grid and display layers

Bounded case-insensitive registry (no shell/code evaluation): New/Open/Save/SaveAs; Undo/Redo; 4View/Perspective/Top/Front/Right; Zoom Extents/Selected; Select All/None; Hide/Show/Lock/Unlock; supported Move/Resize/Rotate; supported creation/removal; Run/Cancel/Export. Autocomplete, argument prompts, unit-aware numeric input, history, Escape cancellation, safe unambiguous Enter-repeat. Shortcuts respect focused native text controls.

Construction grid, working Grid Snap and Ortho, endpoint/midpoint/center snaps on defined geometry, markers and coordinate feedback. Document coordinates, tolerance and candidate priorities. Construction grid is distinct from scientific sensor grid; Rust authorizes final candidates. Semantic room/glazing/shading/context/sensors-results layers have display visibility and edit locks. Hiding/locking never removes Radiance geometry. Camera, selection, display, layout and visibility must not affect scientific hashes/staleness. Separately version display state; preserve v0.1 loading and immutable run bytes.

## Scientific, persistence and platform integrity

Retain immutable inputs/provenance, exact sensor order/count, A/B compatibility/shared scales, stale suppression, Windows process-tree cancel/shutdown, portable project/export/replay, offline calculation and separately acquired engine. Historical comparisons identify their run snapshots and current-design mismatches. Retain Apache-2.0 and reviewed dependency notices. Source remains in its chosen checkout; heavy build/run caches under LOCALAPPDATA/GreenLens. No committed private paths, credentials, engine binaries, build products or private screenshots.

## Required demonstrations

1. Orbit/zoom, geometry/sensor selection, mode toggle and arriving results without reset.
2. Four views and maximize/restore preserve all cameras and projections.
3. Click/add/subtract/contained/crossing selection.
4. Handle and numeric window move/resize saved through authoritative Rust model.
5. Snap and Ortho edit with demonstrated accepted coordinates.
6. Out-of-facade window rejected without document/history damage.
7. One drag/undo/redo restores geometry/parameters/hashes/result staleness.
8. Escape cancels provisional edit without scientific change.
9. Hidden/locked layers leave input hashes and generated engine scene unchanged.
10. Save/Discard/Cancel for replacement/native close, including failed Save.
11. Completed evidence recovery after external revision conflict.
12. Open v0.1, Save As complete copy, reopen without original scratch, export/replay.
13. Real A/B Radiance workflow in new installed Windows package without dev server.

Add meaningful regression and interaction tests (three old presentation tests are insufficient). Run frontend checks, relevant Rust tests, unchanged required science, CLI portability/replay, production packaging and Windows CI. Native screenshots and tested dimensions/scaling required; browser tests/mocks supplementary only. Keep implemented/verified/unverified/blocked records separate. Finish only when all required evidence exists. Report coverage/differences, resolved findings, exact launch/install/artifact paths, compatibility, tests, limitations and repository branch/status. Preserve v0.1 records. No later roadmap implementation.
