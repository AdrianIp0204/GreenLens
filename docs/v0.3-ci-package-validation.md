## Implemented job split and pending scientific gates

GitHub-hosted jobs have a maximum execution time of six hours. A longer configured timeout cannot extend that limit. Standard public Windows runners currently provide four CPUs, 16 GB RAM and 14 GB SSD; each job starts on a fresh VM. Local workstation timings do not establish those runners' timings or resource fit. [GitHub limits](https://docs.github.com/en/actions/reference/limits), [hosted runner specifications](https://docs.github.com/en/actions/reference/runners/github-hosted-runners).

The following jobs are now configured. Their hosted runtimes, artifact sizes and resource fit have not yet been measured. Annual jobs disable matrix fail-fast so a difficult case does not hide the remaining cases; each executes all 8,760 intervals. A 300-minute calculation-step timeout inside a 350-minute job reserves some time for setup and evidence capture below the six-hour ceiling. The native job is the sole Cargo builder; downstream jobs run the exact downloaded CLI without concurrent Cargo processes.

| Job | Required content | Dependency and retained evidence |
| --- | --- | --- |
| `native` — 150 minutes | Exact-source build assertions, locked Rust format/lint/tests, frontend checks/build, unchanged static A–F, static CLI A/B/replay, mandatory weather/provider/context, solar fixture, legacy replay, strict inventories and candidate CLI/NSIS build | Creates `greenlens-ci-cli-<commit>` with executable hash and build-source record. Packaging is an unsigned investigation artifact, before annual acceptance. |
| `selected_hour` — 150 minutes | Shared CLI selected-hour A/B, portable copy with original paths unavailable, selected evidence export and real replay | Depends on `native`; verifies both 1 × 24 result shapes, clean embedded source and actual downloaded CLI hash. Calculation/replay step limited to 120 minutes. |
| `annual` matrix — 350 minutes each | A/shipping, B/shipping, A/reference, B/reference using `annual-single-run.ps1`; all 8,760 intervals and 24 example sensors | Depends on `native`; four complete immutable projects plus selected single-run exports, hashes, resource summaries and logs. All four members must succeed. |
| `annual_convergence` — 45 minutes | Validate the four artifacts and reviewed weather bindings, then call `annual-compare-convergence.ps1` for every sensor and all five metrics | Depends on `native`, `selected_hour` and the complete `annual` matrix. No simulation or replay in aggregation; 240 metric and 96 partition checks for this 24-sensor example. |
| `annual_replay` matrix — 350 minutes each | Shipping A and B complete package replay, all 8,760 × 24 values within max(0.5 lx, 0.5%) | Depends on `native`, `annual` and successful `annual_convergence`; two independent jobs consume the same CLI and original shipping package artifacts. Each calculation step has a 300-minute limit, with hashes, shape, source/weather and fresh native resource telemetry checked. |

The intermediate CLI manifest is tied to the actual executable SHA-256 and clean checked-out Git commit. Each simulation must also return that commit and `source_worktree_dirty=false` in its embedded provenance. Aggregation verifies exact alternative/profile membership, package hashes, complete shape and all three reviewed weather hashes plus interpretation, then rechecks source/weather identity from the newly Rust-validated immutable export records. It does not infer provenance from the current shell. The generic comparison script can compare other common validated weather or dirty exploratory builds; these additional CI assertions deliberately constrain the required example.

`annual-convergence.ps1` already implements the unsplit reference workflow:

```powershell

```

It invokes full A/B for both profiles, then checks 240 comparisons: two alternatives × 24 sensors × DA, cDA, UDI, underlit and overlit. It also checks the UDI partition. It is an appropriate local acceptance entry point once profiles are frozen, but its four sequential annual runs plus optional replay must not be placed blindly inside the existing 150-minute CI job.

The comparison-only `annual-compare-convergence.ps1` now supplies the bounded aggregation interface described in `v0.3-convergence-comparison.md`. It selects four explicit saved run IDs, validates complete evidence through the existing Rust export service, then checks all sensors without starting simulation or replay. `annual-single-run.ps1` supplies the matching explicit `-Alternative A|B -Profile shipping|reference` execution entry point, with a frozen CLI and a new output directory. The original `climate-cli-integration.ps1` remains the A/B convenience workflow. These new orchestration scripts have synthetic regressions; actual final-profile runs and hosted timings remain unverified. If one complete run does not fit the hosted limit, investigate the implementation/resource plan; do not substitute sampled hours for a full-year result.

`annual-matched-sky.ps1` currently accepts scene, sensor and canonical weather files plus explicit numerical parameters. Its defaults are exploratory. Before CI acceptance, bind its candidate transport method and arguments to the frozen shipping implementation and verify that the reference is the identical generated sky. Retain the twelve fixed intervals in `annual-validation-plan.json`, append any missing clear/mixed/overcast class by its declared rule, and run both alternatives without removing difficult sensors/hours. If interval sharding is necessary, add explicit validated fixed partitions and require the aggregator to reject missing, duplicated or unexpected cases. Current scripts do not yet expose that partition interface.

The aggregator must retain the original tolerances: replay max(0.5 lx, 0.5%); same-sky exterior normalization 1%; matched-sky max(5 lx, 5%) at every sensor; DA/cDA/each UDI band within 2 percentage points at every sensor; metric arithmetic/UDI partition within 1e-9 percentage points. Profile investigation failures remain evidence, not optional tests or accepted deviations.

Always-run bounded evidence capture is configured after each job's work. Native diagnostics allow 8 MiB per file and 128 MiB total; selected-hour/annual projects allow 64 MiB per file and 256 MiB total with 5,000-file limits; compact convergence/replay diagnostics allow 8 MiB per file and 64 MiB total. Omitted files are listed. A successful matrix/selected-hour/aggregate/replay job with missing or omitted required evidence fails rather than advertising a complete package. Engine binaries, whole environment blocks and disposable octree/coefficient files are excluded. Uploads retain evidence for 14 days. Runner termination can still prevent an always-run step from executing; artifact absence is never a pass. The aggregate requires every matrix member and rejects incomplete or unexpected sets.
