# Comparing saved annual profiles without recalculation

`scripts/annual-compare-convergence.ps1` compares four explicitly selected saved annual runs: A/shipping, B/shipping, A/reference and B/reference. It invokes only the trusted native CLI's version and selected export commands. It never invokes a simulation, replay or an imported command. PowerShell 7.5 or later is required for timestamp-preserving JSON reads.

The comparison preserves the release's **2 percentage-point per-sensor limit** for DA, cDA, UDI, underlit and overlit. It additionally checks the UDI partition within **1e-9 percentage points** in every run. The default expected sensor count is 24, giving 240 metric comparisons and 96 partition checks. An explicit `-ExpectedSensorCount` may declare another count from 1 to 256; every selected run must match it exactly. A different count is not a substitute for the required 24-sensor release example.

Prepare a selection file outside the source checkout. Replace these illustrative run IDs with the actual immutable IDs; project paths may be absolute or relative to the selection file. A project can appear twice when it retains both alternatives, but all four selected run IDs must be distinct.

```json
{
  "schema_version": "greenlens.annual-convergence-inputs.v0.3",
  "runs": [
    {"alternative":"A","profile":"shipping","project":"shipping/Portable copy","run_id":"00000000-0000-4000-8000-000000000001"},
    {"alternative":"B","profile":"shipping","project":"shipping/Portable copy","run_id":"00000000-0000-4000-8000-000000000002"},
    {"alternative":"A","profile":"reference","project":"reference/Portable copy","run_id":"00000000-0000-4000-8000-000000000003"},
    {"alternative":"B","profile":"reference","project":"reference/Portable copy","run_id":"00000000-0000-4000-8000-000000000004"}
  ]
}
```

Run from the checkout with a built compatible CLI and a new output directory:

```powershell
. ./scripts/dev-env.ps1
./scripts/annual-compare-convergence.ps1 `
  -InputsFile <selection.json> `
  -Cli (Join-Path $env:CARGO_TARGET_DIR 'debug/greenlens.exe') `
  -OutputDirectory <new-comparison-directory>
```

No engine is needed to inspect already saved evidence. The Rust selected-export service performs full retained weather, chunk, metric, process/recipe and checksum validation and enforces the existing archive limits. The script reads each record from that newly validated single-run export, avoiding a mutable-source metadata race or reliance on fast display queries. It retains four compact ZIPs, CLI logs and `convergence.json`; disposable matrices and octrees are not copied. Export acquires the existing short-lived one-writer lock, so close other writers or report a conflict instead of bypassing it.

The comparison requires completed annual mode, all 8,760 intervals, exact sensor count/order/world-space identity, identical weather/time interpretation, occupancy/threshold settings, engine/method identity, adapter/application versions and embedded source commit/dirty state. Complete model inputs must match between shipping and reference for each alternative. A/B must share the Rust comparison fingerprint within each profile, while the profile's complete numerical settings must match across A/B. The two profile settings are allowed to differ. Rust's reader also validates that each is a recognized complete profile.

The report records actual CLI version/hash and each validated simulation's embedded source identity. It does not infer the CLI's source commit from the current checkout. Bind the distributed CLI's build provenance separately during release assembly. Input file paths are not copied into the report; selected run IDs, archive names/hashes, shapes and scientific identities identify the evidence.

Every valid numeric comparison and partition is retained before a threshold failure is returned. A missing/duplicate selection, invalid evidence or incompatible identity writes a failed report without claiming numerical comparison succeeded. The selection is bounded to 64 KiB and four entries. Export reading preserves the shared limits of 5,000 archive entries, 64 MiB per member and 256 MiB total uncompressed, with duplicate/unsafe member rejection. Existing output directories are never overwritten.

The existing `annual-convergence.ps1` remains a convenience workflow that runs all four full-year calculations and then compares them. The new script is the comparison-only route for independently completed CI jobs. Shipping replay is a separate required step and is always recorded as not executed in comparison-only output.

## Producing one matrix member

Use `annual-single-run.ps1` for an independent CI job. All four selection parameters are mandatory: alternative, numerical profile, a frozen native CLI executable and a new output directory. An optional `-EngineDirectory` selects an explicitly acquired compatible engine; otherwise the CLI uses its documented local engine discovery. Missing engine/input and unsuccessful process exits are failures, never skips.

```powershell
./scripts/annual-single-run.ps1 `
  -Alternative A -Profile shipping `
  -Cli <frozen-native-greenlens.exe> `
  -OutputDirectory <new-shipping-A-directory>
```

Each invocation uses the original shared CLI synthetic A/B example and reviewed PVGIS file, validates its original/normalized/time identities and imports it through shared services. As in `climate-cli-integration.ps1`, it sets both alternatives' requested spacing to 1.0 m, producing exactly 24 sensors, with daily 08:00–18:00 occupancy and thresholds 300/100/3,000 lx. It configures and calculates only the requested alternative/profile for **all 8,760 intervals**. It then invokes selected export to revalidate the full saved evidence, verifies that the exported record matches the completed response, and reads the resource record from that immutable export. The CLI file hash must be unchanged from start to finish.

The new directory retains `project/`, `annual-evidence.zip`, the study/import records and per-command stdout/stderr, plus `summary.json`. The summary contains actual CLI hash/version, run ID and embedded source identity, engine/profile/weather identities, exact shape, native resource observations, wrapper wall time, hardware context, package size/hash and a `convergence_selection` entry using the relative `project` path. It does not claim accuracy, replay or installed desktop acceptance. Failure writes `pass:false`; a partial job or rejected export cannot produce a successful summary.

Run four independent jobs for A/shipping, B/shipping, A/reference and B/reference. When their project directories are downloaded under a common aggregation root, construct the comparison selection from the four summary entries, prefixing each relative project path with its downloaded job directory. Preserve explicit run IDs; do not infer the latest run or omit a failed job. The comparator revalidates each saved run again. This does not change the existing two-alternative integration script or wire the workflow automatically.

## Replaying complete shipping evidence

`annual-replay.ps1` runs the trusted frozen CLI against an existing explicitly selected annual evidence ZIP. It accepts one expected alternative or both A/B and rejects extra/mixed static runs, wrong profile/shape, unsafe/duplicate paths or oversized metadata before invoking the CLI. Its preflight is bounded metadata inspection; the Rust replay service performs authoritative complete weather, chunks, checksums, recipes, profile and engine identity validation before starting native calculation. Neither stage executes commands from the package.

```powershell
./scripts/annual-replay.ps1 `
  -Package <shipping-A-annual-evidence.zip> `
  -Cli <frozen-native-greenlens.exe> `
  -OutputDirectory <new-replay-directory> `
  -ExpectedAlternatives A -ExpectedProfile shipping -ExpectedSensorCount 24 `
  -EngineDirectory <compatible-pinned-engine-directory>
```

For one ZIP containing both selected shipping runs, pass `-ExpectedAlternatives A,B`. The wrapper requires exactly 8,760 intervals and every declared sensor for each expected run. It requires successful native completion, finite error statistics, and maximum tolerance ratio ≤1 with the unchanged **max(0.5 lx, 0.5% of reference)** tolerance. It accepts the inclusive boundary; no sampled-hour result can satisfy the complete count. Missing engine, nonzero exit, malformed or truncated response, missing telemetry and failed checks are failures, never skips. The required resources record comes from the new replay execution, not the original simulation; older CLI replay responses without that field are rejected explicitly.

The new directory retains raw CLI response/stderr/version, UTC start/finish and wall time, hardware context, original package/CLI SHA-256 and unchanged-byte checks, expected immutable run/source/weather/profile identities, every returned replay check and native per-process resource telemetry. The frozen v1 resource caps remain 512 MiB per matrix file and 2 GiB for owned scratch and observed runner-plus-engine working set. Working-set sampling is an observation with the measurement policy retained verbatim, not an exhaustive measurement of private memory. The trusted CLI enforces resource limits during execution; the wrapper also rejects missing, inflated or exceeded recorded caps. Existing output directories are preserved.

CI invokes separate A and B replay jobs after all four full annual calculations and the convergence aggregation pass. Each downloads the exact original shipping ZIP and release CLI from the same commit, verifies hashes, and rechecks source/weather identities in the successfully replayed immutable records. Calculation and replay artifacts remain separate. Complete same-engine replay establishes integration reproducibility only; it does not establish independent physical accuracy or desktop acceptance. A hard job/runner termination may prevent final diagnostic collection and must remain a failed/incomplete job.
