# Native annual engine investigation

This is an investigation record, not a completed v0.3 release or a frozen numerical profile. The [machine-readable ledger](v0.3-engine-investigation.json) identifies compact, sanitized experiment snapshots and their SHA-256 hashes. Failed experiments remain in that record. Generated matrices, octrees and raw research files remain in local scratch; they are not distributed as project assets.

The native Windows experiments use the separately installed official Radiance 6.0.2 package, tag `rad6R0P2`. [The dependency inventory](../dependencies/radiance.json) records the executable and library digests, runtime review and notices, including the [gendaymtx embedded license](../third-party/Radiance-gendaymtx-NOTICE.txt). No engine binary is redistributed. The tests execute programs with argument arrays and ASCII matrix streams from paths containing spaces and non-ASCII characters.

## Completed limited checks

- A low-sampling, three-sensor experiment produced finite values for all 8,760 intervals, with 4,411 explicit solar columns. This establishes native shape/order and transport feasibility only. It does not establish the performance or accuracy of the proposed shipping profile on the documented 24-sensor example.
- Eight selected-hour cases, including the first two records, hour 24, a day boundary and the final year record, reproduced the corresponding complete-year sky columns and solar definitions exactly. Selected-hour generation retains up to two preceding dew-point records because the pinned EPW reader uses a three-record moving average.
- The exact projected-solid-angle integral of a piecewise sky agreed with the engine within 0.004103%. The uniform hemisphere check agreed with the independent `E = pi L` relationship within 0.05404%. Six direction/bin checks, direct solar cosine checks and a fully blocked beam check passed.
- A finite-disc aperture fixture exposed a real limitation in the initial centroid-sun method: the sensor on the aperture edge received zero instead of half the visible solar disc. Decreasing `-ds` did not resolve this. The pinned implementation does not subdivide distant sources.
- The investigated `-dj 1` correction has persistent off-centre sampling bias and was rejected. Equal-solid-angle directional transmission with 1,024 and 4,096 rays passed all eleven aperture points; 256 rays failed an offset-edge case. Elevated source radiance prevented the 5 lx absolute tolerance from hiding substantial relative errors. These limited passes do not alone establish a frozen production profile.
- The directional transmission fixture agreed with the same engine's explicit glass/beam calculation at 0°, 30° and 60° incidence within 0.000724%. This is integration verification of the engine's simplified glass treatment, not independent measured-building validation.
- Separate horizontal-overhang and detached-context edge fixtures passed all 36 checks at 1,024 and 4,096 finite-disc samples. The reference independently integrates projected solar-disc visibility using exact ray/plane boundary equations. Increasing its one-dimensional quadrature from 16,384 to 65,536 slices changed values by at most 1.99e-7 relative; the maximum error divided by the fixed tolerance was 0.1031. These checks establish finite direct visibility only, without diffuse transport, glazing or weather.

## Method and source findings

Historical method 2 uses diffuse/ground transport plus full solar-patch transport minus direct-only solar-patch transport plus finite-disc direct transmission. Its complete matched-sky and annual convergence checks fail the fixed thresholds. The provisional method 3 now replaces the reflected solar patch term with explicit-source full transport minus the identical centroid-direct term, then adds finite-disc direct transmission. `gendaymtx -s` retains its luminous ground, including direct-horizontal ground reflection. A separate `gendaymtx -n -D ... -M ...` invocation exports solar sources: combining source export with `-s` would zero their radiance. The native generator regression verifies exact nonzero sources against the historical separate `-d` invocation. No additional exterior ground is present. The [scientific method](v0.3-scientific-method.md) records the complete decomposition, horizon policy, aperture culling and resource limits. Method 3 remains provisional pending complete accuracy and measured full-year resource checks.

The [pinned gendaymtx source](https://raw.githubusercontent.com/LBNL-ETA/Radiance/rad6R0P2/src/gen/gendaymtx.c), [EPW reader](https://raw.githubusercontent.com/LBNL-ETA/Radiance/rad6R0P2/src/gen/loadEPW.c), [Reinhart basis](https://raw.githubusercontent.com/LBNL-ETA/Radiance/rad6R0P2/src/cal/cal/reinhart.cal), [source sampling](https://raw.githubusercontent.com/LBNL-ETA/Radiance/rad6R0P2/src/rt/srcsamp.c) and [source dispatch](https://raw.githubusercontent.com/LBNL-ETA/Radiance/rad6R0P2/src/rt/srcsupp.c) define the implementation conventions. The [official matrix-methods tutorial](https://www.radiance-online.org/learning/tutorials/matrix-based-methods) describes the direct correction principle. No tutorial models or diagrams are copied.

The EPW midpoint is `hour - 0.5` in fixed local standard time; there is no daylight-saving adjustment or dropped nighttime interval. Direct EPW input preserves dew-point information that would otherwise require an explicit WEA policy. The actual basis test confirms north-first bins increasing towards east. The pinned irradiance coefficient convention already includes the projected hemisphere factor; no extra factor of pi is applied during matrix multiplication.

## Remaining work

Four completed matched-sky profile investigations failed the unchanged per-sensor tolerance. The first failed record used an integer-rounded diagnostic tolerance; the script was repaired to use `max(5.0 lx, 5% of reference)` and the original failure record remains disclosed. The latest higher-sampling, lower-cutoff centroid investigation passes ten of twelve predeclared hours and fails intervals 1912 and 6320. Its identical MF2 sky is used for that matched-sky comparison; a different sky basis is not substituted for the reference. Single-sensor follow-up also shows material reference sampling variation, so merely increasing a nominal sample count is not proof of reference convergence.

The isolated high-sampling transport snapshot records three ambient bounces in its declaration and process arguments. A dot-sourced research helper reset the requested bounce parameter. Those results establish only the recorded three-bounce comparison, not convergence of the proposed eight/nine-bounce profiles. The script now preserves that parameter explicitly, and the nine-bounce follow-up is recorded separately.

The finite-disc correction is integrated into the Rust adapter and has completed a real full-year resource probe. Actual shared-service A/B shipping exports each replayed all 210,240 values with zero observed lux differences using the same frozen CLI; this is integration verification, not independent physical validation. The caller measured 341.539 and 343.217 seconds, but this executable did not report replay memory or scratch telemetry. Numerical acceptance remains open. The winter interval 8504 direct-corrected prototype fails eight of 24 sensors at MF2 with 131,072 coefficient samples (maximum relative difference 9.51%), and fourteen sensors when only reflected solar uses MF4 at that sample count (12.30%). These are diagnostic comparisons, not final acceptance runs. Full-year accepted A/B runs, annual shipping/reference metric convergence and installed annual desktop acceptance remain outstanding. Research timings collected concurrently with other engine checks are not exclusive-host benchmarks. A null or zero peak in an early short-process measurement means that polling did not capture it, not that the process used no memory.

The bounded 128-positive-source, 24-sensor solar experiment took 350.160 seconds. Scaling by the 4,058 positive-radiance source count estimates 3.08 hours for annual shipping solar transport alone; this is an estimate, not an annual measurement. That cost motivated the standard direct-solar matrix correction now under investigation. The explicit-source path remains a slower fallback; there is no release wall-time threshold that warrants weakening numerical requirements.

A complete MF4 diffuse/ground sky matrix contains 226,165,911 bytes, fitting the 512 MiB per-file scratch bound. Native generation took 38.579 seconds with a sampled peak child working set of 249,835,520 bytes. Nine unusually-bright sky warnings are retained in its process record. Scratch limits are distinct from, and do not change, the shared evidence-package limits.

The corrected Rust shipping-profile resource probe completed 8,760 × 24 values in 317.948 seconds (2026-10-11 06:23:48–06:29:06 UTC). All 210,240 lux values were finite and nonnegative without clamping. Peak engine working set was 68,231,168 bytes; sampled runner-plus-child working set was 78,712,832 bytes; whole scratch peak was 136,546,918 bytes. The largest matrix was 56,693,520 bytes. Other verification engine work and some Cargo work overlapped this observation. This supports practical feasibility and stable integration settings, while numerical profile acceptance remains open.
