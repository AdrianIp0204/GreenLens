The frozen CLI is application 0.3.0 from clean source `438ff2214c52554b2300eacd9547e905eec95fcd`, SHA-256 `0d1167b1e8c24bebbfc93f498a87b9919f57b71b46f5f5ae3a1545a22953a5b6`. Their recorded application source remains `c3d3d59a57ca1def890001a1df5d03d58cc72738` with a dirty-worktree flag. Reading them with the newer CLI does not relabel their method, profile, source, result or metric identities.

## Procedure

Run the versioned harness with a new output directory; it refuses to overwrite prior evidence:

```powershell
$base = Join-Path $env:LOCALAPPDATA 'GreenLens'
$cli = Join-Path $base 'verification/v0.3 method3 CLI 438ff22'
./scripts/verify-historical-methods.ps1 `
  -Cli (Join-Path $cli 'greenlens.exe') `
  -BuildRecord (Join-Path $cli 'build.json') `
  -SourceProject (Join-Path $base 'native-verification/v0.3-candidate-01/Portable annual copy') `
  -LegacyPackage tests/fixtures/legacy-static-v0.1.zip `
  -OutputDirectory (Join-Path $base 'verification/historical-methods-new-run')
```

The installed pinned native Radiance package must be discoverable, or supply `-EngineDirectory`. The harness uses the Rust CLI for all evidence copying, import validation, export and simulation; no package-supplied commands are executed. It inventories source bytes, makes a complete verified copy, reads interval 1908, compares historical cDA, exports only historical A, replays that complete annual run, then replays the original published v0.1 static A/B fixture. The actual run outputs are under `%LOCALAPPDATA%/GreenLens/verification/v0.3 historical methods 438ff22 retry1 空間`.
