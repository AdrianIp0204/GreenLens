## Bounded generator and encoding

`annual_primary::HammersleyPrimary::new(&[Sensor], count)` implements `Iterator<Item = Result<Vec<u8>>>`. It stores at most 256 origins and emits one short record at a time. Supported preparatory generator counts are 16,384, 65,536 and 262,144; only the first two occur in current complete profiles. Inputs require finite positions, unique bounded IDs and exact world-up normals. The largest generator shape describes 67,108,864 rays without allocating them.

The rule is `greenlens.hammersley-cosine-primary.v1`. In authoritative sensor order, repeat primary indices `i = 0..N-1` at every sensor:

```text
r = sqrt((i + 0.5) / N)
phi = 2*pi*radical_inverse_base2(i)
direction = (r*cos(phi), r*sin(phi), sqrt(1-r*r))
origin = sensor.position + (0,0,0.0001)m
```

No rotation, scrambling, random seed or aperture culling is applied to these hemisphere rays. One continuous native process and stdin stream cover all sensors. The separately versioned finite-sun direct-only culling policy remains unchanged. Arithmetic uses separate sine/cosine and `sqrt(1-r*r)` operations, preserving their floating-point rounding.

Encoding `greenlens.primary-ascii-e17-lf.v1` writes six finite values as lowercase ASCII scientific notation, **17 digits after the decimal point (18 significant digits)**, signed integer exponents without `+` or redundant zeros, single spaces, one LF, no BOM, and preserved signed zero. Records are bounded by 132–192 bytes. This does not claim C# `G17` byte identity.

Six pure generator tests verify independent base-2/quadrant values, malformed input, every direction at all three counts, maximum lazy shape, origin/order, golden bytes and identical regeneration. Eighteen scalar samples agree with the frozen executed research generator within the predeclared absolute component tolerance `2e-15`. Its source SHA-256 is `49ccb427479ee2951c1b94753dafecd318b519511c3aca7c6b629eed695045cd`. The independent two-sensor encoding golden is 32,768 records, 4,489,218 bytes, SHA-256 `7dd8b4a77fede4c7e9030c015dff5003916fd9ba09f99c01d06f86808914b895`. Its expected bytes were independently encoded from research doubles before running Rust.

## Execution and scientific normalization

`AnnualProfile::coefficient_arguments` produces radiance queries with **no `-I+`**, `-c N`, `-V+`, one worker and the pinned Reinhart binning library. Full and direct processes differ only in the declared bounce depth; they consume independently regenerated, byte-identical streams and the same scaled 360-degree receiver. `coefficient_sensor_text` rejects method 5 rather than allocating an expanded file. The unit finite-transmission receiver is unchanged.

Process indices are fixed:

| Index | Stage |
| --- | --- |
| 0 | `gendaymtx -s`, diffuse and ground |
| 1 | `gendaymtx -m MF -d -D/-M`, solar patches and finite sources |
| 2 | Compile unit finite-transmission octree |
| 3 | Compile scaled coefficient octree |
| 4 | Stream full coefficients |
| 5 | Multiply diffuse/ground matrix |
| 6, if sources exist | Stream paired ab0 coefficients |
| 7–8, if sources exist | Multiply full and direct solar patch matrices |
| Following stages | Existing bounded finite-sun batches with emitted rays |

This is six base processes without solar sources, or nine plus nonempty finite batches with sources. The helper validates every coefficient shape and rejects every negative/nonfinite full-minus-direct RGB bin before multiplication. Ground occurs once in the diffuse/ground matrix. Solar patch terms are gated to emitted-source intervals, preserving the explicit horizon policy and selected-hour dew-point context.

Because `-c N` returns the mean, assembly is:

```text
E_RGB = pi/scale * (C_full * diffuse_ground
                 + C_full * solar_patches - C_direct * solar_patches)
      + finite_direct_RGB
```

Apply `pi/scale` once, with **no further division by N**. The authoritative RGB-to-lux convention remains unchanged. Negative/nonfinite reflected RGB is rejected, not clamped or compensated by a positive diffuse term. The retained weather zero-DNI/zero-DHI invariant still applies. These are method assumptions and tested limited behaviors, not arbitrary-building validation or certification.

## Portable receipts and supervision

Platform-neutral types are exported by `annual_primary`: `ExternalPrimaryContract`, `PrimaryStreams`, `PrimaryStreamRecord`, `PrimaryPurpose`, `InputReceipt`, and `StreamTelemetry`. Static or historical inspection does not depend on Windows process APIs.

Retain `annual-primary-streams.json`, schema `greenlens.annual-primary-streams.v1`, containing `schema_version`, `contract`, `sensor_sha256`, `sensor_count`, `sky_rows` and ordered `records`. Each record contains `purpose`, `process_index`, `input` (bytes, records, SHA-256), `matrix_sha256` and `resources`. Full is mandatory; direct is present exactly when solar sources exist. Counts equal sensors × N; receipt bytes lie within the encoding bounds; input hashes/counts/bytes match between full and direct. The optional recipe key `primary_streams_sha256` pins this file and remains absent in methods 2–4.

A receipt identifies bytes successfully written to the pipe. Successful process exit, complete expected matrix shape, finite values and a fully terminated owned Job are additionally required. Output hashes identify disposable matrices; replay compares exact regenerated input receipts while allowing the specified numerical tolerance for stochastic outputs. Reading an inspector does not regenerate millions of rays. Full verification checks immutable pins, seals, compiled profiles and receipts; replay exercises generation.

`annual_stream::execute_in_run` requires a fresh stage directory strictly below the canonical owned run root, rejecting reparse traversal. Child cwd and resource scans use the whole run root, preserving root-relative arguments and counting other stages' scratch files. Atomic Windows Job assignment occurs before child execution. The synchronous nonblocking byte pipe preserves partial-write suffixes and hashes only written bytes; there is no writer thread or unbounded join. Parent exit alone is not success. Cancellation/deadline/failure terminates the Job and bounds cleanup. Completed matrix output moves from its stage to the root only after shape validation. No expanded primary file is retained.

Stream resource schema `greenlens.stream-resources.v2` retains actual parent-child lifetime peak, sampled runner-plus-child working set, sampled runner-plus-whole-Job working set, scratch peak, sample/write counters and atomic-assignment flag. Only actual child measurements map into unchanged `AnnualProcessResources`; whole-Job observations stay separate. Both exact historical measurement-policy strings remain readable for methods 2–4; method 5 requires its new policy. File-backed method-5 stages use a separate 7,200-second deadline wrapper; historical execution behavior stays unchanged. Sampling includes scan/query time plus a 20 ms sleep and scheduling overhead, not a guaranteed 20 ms cadence. Shared pages are counted across processes; working sets are not private memory.

The unchanged resource limits are 512 MiB per scratch file, 2 GiB total owned scratch and 2 GiB observed working-set bounds. Portable evidence remains subject to 64 MiB per member, 256 MiB total and 5,000 entries. Compact receivers, receipts, recipe, logs, resources and series are retained; octrees and large matrices remain disposable. Failed streamed stages preserve original nested diagnostics plus sanitized top-level `annual-primary-failure.json`; they never become completed runs.

## Verified scope and remaining acceptance

The isolated native Rust generator/stream bridge passed **12 of 12** cases on 11 October 2026 in 1,023.75 seconds: uniform hemisphere, black enclosure with glass, reflected A/B coupling, and independent clear-aperture A/B fixtures, at both counts. Both used MF2. Uniform tolerance was 1%; aperture tolerance was `max(5 lx, 5%)`, with independent quadrature convergence within 0.1%. Full/direct residuals were nonnegative; uniform and black-glass residuals were exactly zero.

The [complete compact result](evidence/v0.3-engine/rust-primary-stream-bridge.json) retains all values, arguments, receipt/output hashes, measurements and the pre-run declaration. Raw matrices and exact source snapshots remain in its relative local verification directory. The binary was built with uncommitted isolated source at observed commit `fe630b636cdaa758ad9742a5b9bbe3cc53240c7a`; the exact binary and module hashes are recorded. This is not a clean-release binary claim. That bridge used historical stream resource schema v1. Current integrated supervision uses v2 and has separate native synthetic lifecycle regressions.

The bridge establishes limited generator, normalization, aperture and coupling behavior. It does not qualify method-5 annual settings. Required acceptance still includes all 24 sensor × 12 hour × A/B controlled references, both declared sensitivities, unchanged candidate agreement thresholds, full-year shipping/reference A/B convergence, replay, measured budgets, installed desktop workflow and exact-source CI. Incomplete or failed reference evidence cannot qualify a candidate.

Integration preparation passed all 82 runner tests, then 43 non-engine adapter tests and the focused receipt/timing and selected-export regressions after the final resource-policy changes. Six ignored synthetic child entrypoints are exercised by their parent tests; five actual-engine checks were explicitly excluded from this preparation pass. Workspace Clippy with warnings denied, formatting and whitespace checks passed. A tiny native synthetic early-exit fixture also verified actual stream-resource v2 failure retention: 930 generated records, 64,635 written bytes, terminated process tree and no completed matrix/receipt. Independent diagnostic collection retained exactly one sanitized file without changing its source bytes. These process/metadata checks are separate from the earlier real-engine bridge and annual scientific acceptance.
