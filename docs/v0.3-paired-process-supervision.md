# Paired research process supervision

This is a research-harness lifecycle check, not evidence that an annual numerical method is qualified. It changes neither the sealed controlled-reference supervisor nor already-running workers. The failed full-year method-4 calculations and earlier paired research records remain unchanged.

## Observed failure

A synthetic native parent exited successfully after spawning a child that retained its inherited standard streams. The earlier paired supervisor stopped polling when the parent exited, then waited indefinitely for stream completion. With a declared 10-second limit, an independent watchdog observed it still blocked after 20.0954275 seconds. Only termination of that exact synthetic child released the supervisor and allowed a failed record to be written. The original source bytes, process records and watchdog observation are retained locally; the public evidence contains their digests and a sanitized account.

This demonstrated a supervision defect. It did not demonstrate altered numerical input or output in an existing Radiance run.

## Bounded replacement

The original C# [native process helper](../scripts/annual-paired-native-process.cs) launches through `CreateProcessW` with `STARTUPINFOEX`, `PROC_THREAD_ATTRIBUTE_JOB_LIST` and `PROC_THREAD_ATTRIBUTE_HANDLE_LIST`. Job membership is established during process creation, before executable code may create descendants. The job is configured to terminate its members when its non-inherited owner handle closes. Only the three child-side standard-stream handles are inherited; the parent closes its copies immediately. These Windows 10-or-newer APIs and their at-creation behavior are documented by [Microsoft Learn](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-updateprocthreadattribute) and [Microsoft's engineering explanation](https://devblogs.microsoft.com/oldnewthing/20230209-00/?p=107812).

The helper accepts an executable and argument array, applies Windows argument quoting without a shell, preserves binary streams, and overrides `RAYPATH` only in the child's copied environment. No global environment is changed. Standard input has no managed write buffer, avoiding a buffered tail that could make synchronous close bypass the deadline. The supplied producer or file-copy operation provides its own bounded buffer.

The [PowerShell supervisor](../scripts/annual-paired-process.ps1) keeps one deadline active until the direct process has exited, the job is empty, verified observed descendant handles have signaled exit, input has completed, and both output streams have settled. Parent exit and stream EOF alone are insufficient: a native fixture observed job accounting settle slightly later. Conversely, job accounting can reach zero before a terminating process handle signals; observed member handles are retained until cleanup. On failure, the supervisor terminates the job and cancels pending work, then allows at most five seconds for cleanup. It does not synchronously await unfinished tasks. A partial or timed-out operation is recorded as failed.

The existing limits remain 7,200 seconds, 2 GiB observed runner-plus-job working set, 2 GiB scratch and 512 MiB per retained file. Working set is sampled across live job members; an opened PID is checked for membership before its memory is counted. This is observed resource supervision, not an assertion that every lifetime peak was sampled. Atomic job-assignment failure is explicit; there is no fallback to an unowned child.

Disk checks run at five-second intervals and at finalization. They use the owned stdout stream's live length and fresh `GetFileSizeEx` handles for other files, because Windows directory-entry lengths can remain stale while a writer is open. Two synthetic writers each flushed 131,088 bytes and kept their handles open. The 4 KiB stdout file cap stopped its writer after 5.244 seconds; the 8 KiB scratch cap stopped its writer after 5.216 seconds. Both failed for the resource limit before their 20-second deadlines or natural exit. These are sampled limits, allowing growth between checks, rather than filesystem quotas.

## Reproduction and evidence

From the checkout on native Windows with PowerShell 7.2 or newer:

```powershell
pwsh -NoProfile -File scripts/test-annual-paired-native-process.ps1
pwsh -NoProfile -File scripts/test-annual-paired-process.ps1
```

Both scripts create new synthetic fixtures below `%LOCALAPPDATA%/GreenLens/verification`, retain their results, and require no Radiance engine. The final native primitive passed all 12 checks of argument values, empty strings, quotes, backslashes, Unicode paths, child-only environment configuration, exact 2 MiB binary transfer, exit status, unrelated-handle exclusion, job termination/disposal, and blocked input after parent exit. The final wrapper passed all 16 checks of successful transfer, nonzero and incomplete execution, deadlines, resource caps (including live open files), path rejection, and the two inherited-pipe failure modes. The latter failed within 10.205 and 10.125 seconds for declared 10-second deadlines, with completed stream cleanup and no surviving fixture processes.

The [sanitized evidence](evidence/v0.3-engine/paired-process-supervision.json) records actual final-source results and hashes; its adjacent manifest seals the public record. No engine accuracy, annual convergence, hosted CI result, packaging result or native desktop acceptance follows from these tests. The generated-primary numerical experiment is documented separately.
