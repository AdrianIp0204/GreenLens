# Paired research comparison against qualified references

`scripts/annual-compare-paired-reference.ps1` reads retained research evidence. It does not run Radiance, replay commands, load code from an evidence directory, or promote a result into a GreenLens project. It requires PowerShell 7.5 or newer and trusted verification sources from this checkout. There is no Python dependency.

The script first calls `Collect-ReferenceEvidence` from `scripts/annual-collect-reference.ps1`, which implements the [reference protocol](v0.3-reference-protocol.md). It retains that fresh snapshot and refuses candidate acceptance unless all 24 A/B weather cases, all 576 sensor values, and both fixed sensitivity cases are qualified. A partial snapshot or a failed sensitivity cannot be accepted. Previous scientific failures remain unchanged.

The candidate inputs must contain exactly one A/B pair from the [Hammersley experiment](v0.3-paired-hammersley-investigation.md): either the declared `candidate` tuple or the declared `higher` tuple. Mixed tuples, other modes, reordered cases, missing sensors, changed inputs and unsupported helper identities are rejected. The original twelve weather intervals and all 24 stable sensor IDs are mandatory.

The reader checks:

- Exact source/helper identities, model, ordered sensors, reviewed weather, MF2 sky, solar sources and engine/library hashes. The solar-year matrix is pinned to the identical original A/B input SHA-256 `70b9560f9f461bf1db26985f3b3df894546b92c27bc94b623a9d0f6a84c416c4`. This is an explicit retained-input binding, not an independently regenerated sky claim.
- Full/direct stream receipts, regenerated with the trusted producer into a discard stream. No ray file or native process is created. Both receipts must match every byte, ray count and hash.
- All 19 native process records in their required order, including exact argument arrays, successful exits, whole-job and stream completion, resource limits, input counts and retained output sizes.
- Bounded ASCII RGB matrix shapes and finite nonnegative channels. Every selected annual sky column is checked, and all three coefficient products are independently multiplied. The arithmetic check retains its existing ASCII tolerance of `max(1e-7, 1e-5 × expected)` per RGB component; this is separate from the physical comparison threshold.
- Finite-disc transmission recomputed from retained native outputs using only the trusted 1,024- or 4,096-direction policy. Each component of `pi/100 × (full diffuse + full solar − direct solar) + finite direct` and the Radiance RGB-to-lux conversion is recomputed and checked against the saved candidate report. There is no second primary-sample divisor, discarded RGB channel, repeated ground term or clamping of negative residuals.

The final comparison uses the unchanged per-sensor limit **`max(5 lx, 5% of the qualified reference)`**. All 576 signed differences, absolute errors, permitted errors and pass/fail flags are retained. Every negative coefficient bin is retained separately and prevents a pass even if the resulting lux differences happen to meet the limit. The script checks hashes again after reading to reject a changing evidence snapshot.

## Running the comparison

Use complete immutable directories produced by the declared harnesses. The output directory must be new. For example, from the source checkout:

```powershell
$v = Join-Path $env:LOCALAPPDATA 'GreenLens/verification'
$baselines = @('<complete A baseline shards>', '<complete B baseline shards>')
$sensitivities = @('<qualified B:8512 sensitivity directory>', '<qualified A:4116 sensitivity directory>')
./scripts/annual-compare-paired-reference.ps1 `
  -CandidateA (Join-Path $v 'v0.3 Hammersley A candidate native 空間') `
  -CandidateB (Join-Path $v 'v0.3 Hammersley B candidate native 空間') `
  -Variant candidate -BaselineDirectories $baselines `
  -SensitivityDirectories $sensitivities `
  -OutputDirectory (Join-Path $v ('paired-qualified-comparison-' + [guid]::NewGuid()))
```

Replace the angle-bracket directory placeholders with the retained full set. Repeat separately with `-Variant higher` and its A/B directories when that evidence exists. Do not combine tuples or pass a precomputed collection JSON in place of baseline/sensitivity evidence.

Outputs include `reference-collection.json`, `A-recomputed.json`, `B-recomputed.json`, the three independent product checks for each alternative, `comparison.json` and a checksum seal. A rejected/incomplete input produces `failure.json` and a failing exit status; a failed numerical comparison still retains every comparison row before failing. Files already present at the requested destination are never overwritten. No directories or machine configuration are copied into these records.

## Verification scope

The original synthetic regression is `scripts/test-annual-compare-paired-reference.ps1`. It checks non-gray matrix products, selected-column order, matrix truncation/nonfinite/duplicate-header rejection, changed hashes, source paths, negative coefficient and assembled residual preservation, both finite-cap formulas, stream receipts, failed or incomplete process records, frozen tolerance boundaries, complete coverage, mixed tuples and incomplete reference/sensitivity rejection. Synthetic process records are explicitly fictional and are never passed to the public reference collector as engine evidence.

The final 56-check synthetic run passed without launching an engine. On 11 October 2026, a read-only check of the completed native A candidate also passed: 12 cases, 288 sensor values, all 19 process records, regenerated primary-stream receipts, finite-disc components and all three independent matrix products. Each product checked 864 RGB components; their maximum error-to-arithmetic-tolerance ratios were 0.048983, 0.044301 and 0.041468. No negative coefficient bins were present. The reader launched no engine and did not compare against a qualified reference.
