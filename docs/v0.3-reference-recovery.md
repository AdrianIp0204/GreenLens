# Controlled-reference reporting recovery

The original controlled-reference harness contained a PowerShell array-expression error: `@($rounds/4,$rounds/2,$rounds)` attempts division involving an array. The corrected expression, `@(($rounds/4),($rounds/2),$rounds)`, produces the declared 64/128/256 and 128/256/512 ladders. This reporting correction changes no engine argument, input, estimator, repeat count or tolerance.

Original native directories, declarations, source snapshots and outputs remain immutable. Recovery requires a **new directory** and exactly the first six successful, bounded process records from the explicitly pinned original harness. It verifies matching scientific declarations and input hashes, copies and hashes the original outputs, retains the original process records and timestamps, and records their reuse in `recovery.json`. The expensive 256-round process is not repeated. A partial, failed, altered or differently configured process cannot be reused.

After reuse, the corrected harness computes the original convergence checks. It runs the predeclared 512-round escalation only if required, and continues the original interval order. Recovery alone does not qualify a reference. The independent collector recomputes all means, transitions, disjoint blocks and escalation prefixes from raw output, verifies recovery lineage, and still requires all 24 design/interval cases plus both fixed sensitivity cases.

The optional argument is `-RecoverDirectory <original-shard-directory>` on `scripts/annual-controlled-reference.ps1`; the normal `-OutputDirectory` must be new. `OriginalJobDirectory`, alternative and interval order must match the original declaration. Recovery never executes commands taken from evidence.

Forty synthetic regression checks exercise exact reuse and rejection of modified records, arguments, inputs, hashes, resources and timestamps. They also reproduce the original expression failure and evaluate the corrected ladders. These tests execute no simulation engine and do not count as numerical reference qualification. Native recovery status and final scientific results are recorded separately.

The original reference supervisor samples directory-entry file sizes. A later paired-supervisor regression established that these sizes can lag while a Windows writer keeps a file open. Its retained `sampled_scratch_peak_bytes` therefore reports the observed metadata value, not an exact in-flight disk peak. Successful reference outputs are independently checked after closure, including the exact 6,144-row × six-channel 256-round output, file lengths, hashes and complete retained inventory. Those closed-file checks can establish that the retained evidence fits the declared limits; they do not retroactively prove the original sampler's live enforcement. The frozen reference helper and active workers are unchanged, and recovery does not rerun or rewrite successful numerical outputs merely to change telemetry.

The paired-primary experiment has a separate research input-streaming repair, described in [its retained evidence](evidence/v0.3-engine/paired-grid-memory-remedy.json). It preserves the failed memory-cap attempt, the 2 GiB cap and both exact ray files. It does not modify the sealed reference supervisor or the production adapter.
