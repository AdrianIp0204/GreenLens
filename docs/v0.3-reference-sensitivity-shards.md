# Scheduling the fixed reference sensitivities

The [sealed reference protocol](v0.3-reference-protocol.md) requires three variants at all 24 sensors for B at interval 8512 and A at interval 4116. `scripts/annual-reference-sensitivity.ps1` can run one named variant in a new evidence directory. Omitting `-Variant` runs all three in their original order. This changes scheduling only: each variant already used a separate `oconv` and `rcontrib` process.

The supported names remain `scale10000`, `weight1e10` and `depth10-24`. The exact qualified baseline repeat count, complete round-major sensor input, source geometry, direct correction, engine arguments and normalization are unchanged. The source-scale check retains its per-channel `1e-5` relative tolerance and exact-zero rule. Weight and depth checks retain `max(0.1 lx, 1% of baseline)` at every sensor. A failed variant remains a failed sensitivity; the collector never substitutes another result.

Each new declaration uses `greenlens.controlled-reference-sensitivity-shard.v1`. It retains the full ordered three-variant plan and an `executed_variant_names` array containing either one name or the complete plan. It also binds the complete baseline declaration and exact hash, qualified final rung, all original raw/component/input hashes, harness and supervisor identities, limits and scientific policies. `completed` in a shard report means its requested execution completed. `case_complete` requires all three variants in that directory. Neither flag establishes release acceptance.

The collector revalidates every raw result, scene, process and comparison before grouping shards. It compares every declaration field within a case except the shard's creation timestamp and executed subset; unknown scientific fields remain part of that identity. Duplicate case/variant declarations are rejected even when their outputs agree. Mixed baseline declarations, repeat rungs, input hashes or helper identities are rejected. Missing variants are reported by name and prevent qualification. The final collection still requires exactly two complete sensitivity cases alongside all 24 qualified reference cases. The paired comparator's 576-value requirement and `max(5 lx, 5%)` limit are unchanged.

The original serial schema, `greenlens.controlled-reference-sensitivity.v1`, remains readable with its reviewed source SHA-256 `88400209ed579398253903feb7fe7abb22c53bfafec85433b89001578297db01`. It is not silently reinterpreted as a shard. Original baseline evidence and the sealed protocol are never rewritten.

## Preparation and execution

For a qualified B baseline, prepare one declaration without launching an engine:

```powershell
$v = Join-Path $env:LOCALAPPDATA 'GreenLens/verification'
./scripts/annual-reference-sensitivity.ps1 `
  -BaselineDirectory (Join-Path $v '<qualified B baseline directory>') `
  -OutputDirectory (Join-Path $v ('B-weight-preflight-' + [guid]::NewGuid())) `
  -IntervalIndex 8512 -Variant weight1e10 -PrepareOnly
```

Use the actual retained baseline directory in place of the placeholder. After reviewing the declaration and obtaining an available supervised worker slot, invoke the same command without `-PrepareOnly` and with a **different new output directory**. Existing directories are not resumed or overwritten. Use interval 4116 and the matching A baseline for A. Supply all six completed variant directories to `annual-collect-reference.ps1 -SensitivityDirectories`, together with all required baseline shards. A complete three-variant directory can replace the three separate directories for that case, but supplying both is a duplicate error.

## Verified scope

On 11 October 2026, 20 pure sensitivity helper checks, 59 existing collector checks and 42 new shard reader/aggregation checks passed. The new tests exercise real reader code with original synthetic numeric arrays and explicitly fictional process records: serial/sharded equivalence, unordered directory submission, missing/duplicate/failed variants, unknown or changed identities, legacy source selection, incorrect arguments/limits, changed raw results, truncation, nonfinite values and excess output. No engine process is launched by those tests; they do not establish scientific qualification.

An actual B:8512 `-PrepareOnly -Variant weight1e10` invocation also passed against the qualified retained baseline. It verified the unchanged source/input hashes and recomputed baseline convergence, then wrote the shard declaration without native variant execution. This exposed and verified a preflight correction: expected basis and extracted hourly-sun text now follow the trusted writer's CRLF-to-LF conversion. The original upstream/source bytes and their hashes remain unchanged; lone carriage returns are not normalized away.

Native sensitivity results, complete reference qualification and candidate agreement remain pending. Hosted execution of the new shard tests is not claimed here.
