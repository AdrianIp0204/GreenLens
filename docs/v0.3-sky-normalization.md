# Annual sky-only normalization verification

`scripts/annual-sky-normalization.ps1` verifies the pinned native engine's integration of the **identical generated piecewise sky**, an original unequal-channel uniform hemisphere, and Reinhart patch ordering. It covers MF2 and MF4. It does not validate room transport, explicit solar-disc visibility, indirect solar transport, annual convergence, or installed desktop behavior. The known centroid/edge failure in `scripts/annual-analytical.ps1` is retained unchanged and is not replaced by a passing sky check.

Run from the repository with PowerShell 7.5 or newer:

```powershell
pwsh -NoProfile -File scripts/annual-sky-normalization.ps1
pwsh -NoProfile -File scripts/test-sky-normalization.ps1
```

Both default to new directories containing spaces and non-ASCII characters under `%LOCALAPPDATA%/GreenLens/verification`. `-OutputDirectory` must be new; `-EngineRoot` may identify the separately acquired engine. Missing tools or mismatched hashes fail; there is no optional engine skip. The second command includes the required native suite and focused regressions, so running it alone is sufficient. No Cargo build, Python runtime, network service, full annual calculation or UI is required.

## Independent reference and interpretation

For an upward horizontal sensor and a patch bounded by elevation `a0..a1` and azimuth width `2*pi/n`, the exact projected solid angle is:

`W = (pi/n) * (sin(a1)^2 - sin(a0)^2)`.

This integrates `omega_z dOmega` over the patch rather than using its center direction times its solid angle. Ring separation is `alpha = pi/2/(7*MF+0.5)` with base ring counts `[30,30,24,24,18,12,6]`, each subdivided by MF. The zenith cap weight is `pi*(1-sin(7*MF*alpha)^2)`. The upper weights sum to pi within `1e-12`. The lower hemisphere is bin 0: it contributes zero to an upward sensor and pi times its RGB radiance to a downward sensor. This also tests that ground is included once.

Each reference channel independently sums `L_patch[channel]*W_patch`. The test compares native `rtrace -I+` irradiance directly with these sums; it adds no extra pi factor to native output. Lux is then `179*(0.265074126*R + 0.670114631*G + 0.064811243*B)`. Both each RGB channel and converted lux must agree within **1%**, unchanged from the release normalization requirement. This is a visible-RGB convention, not a conversion from arbitrary broadband solar irradiance.

Separate `.dat` files and `colordata` reconstruct all three matrix channels. No equality of R/G/B is assumed. The original uniform fixture has radiance `(0.25,1,2)`, for which `E=pi*L` is analytical. A synthetic three-record EPW uses varying dew point and unequal sky/ground colors. These records are original non-climatic test data, not a full-year weather acceptance fixture. The real case uses the production neutral sky and ground colors.

The real source is the reviewed PVGIS file in `dependencies/weather.json`. Its original SHA-256 is checked. Only the documented normalization is reproduced, and the complete normalized bytes must match the provider's pinned normalized SHA-256 before any selected records are used. This is deliberately **not** a second general EPW parser. The fixed interval is 1908: March 21, hour-ending 13, representative local-standard time 12:30, fixed UTC+480 minutes. Source indices 1906–1908 retain the preceding dew-point state; the final of the three generated columns is tested. Source years remain provenance, and no OS timezone or DST is used. Hourly accumulated Wh/m² and mean W/m² have equal numeric values for these one-hour intervals, but remain distinct quantities.

`gendaymtx -O0 -m MF -c ... -g ... -s selected.epw` generates diffuse sky **and its complete ground term**, which includes reflected direct-horizontal illumination. There is no additional ground surface/term. Explicit solar-disc irradiance is excluded from this sky-only test. The comparison is against the exact generated sky; it does not demand equality to a different sky generator, or treat sky radiance as an independent observation of weather illuminance.

The directional fixture assigns unique, unequal RGB values to every bin. Rays at the lowest-ring north/east/south/west centers, zenith and nadir must return the correct triplets with absolute RGB error no greater than `1e-6`. Expected bins are `[1,16,31,46,577,0]` for MF2 and `[1,31,61,91,2305,0]` for MF4. This exercises north-first, east-positive ordering, zenith placement and ground index independently of an approximately symmetric real sky.

The native trace uses one worker, explicit ASCII RGB output, `-ab 1 -ad 262144 -as 0 -aa 0 -ar 256 -av 0 0 0 -lw 1e-10 -lr 16 -dt 0 -dc 1 -dj 0 -ds 0.01 -st 0 -ss 0 -u-`; directional bin queries use `-ab 0`. No ambient cache is supplied. Executables use argument arrays and binary-safe output streams through the existing bounded native helper. Each process has a 120-second timeout with tree termination. Library configuration applies only to children.

Primary source review: [pinned gendaymtx manual](https://github.com/LBNL-ETA/Radiance/blob/rad6R0P2/doc/man/man1/gendaymtx.1), [pinned gendaymtx implementation](https://github.com/LBNL-ETA/Radiance/blob/rad6R0P2/src/gen/gendaymtx.c), [pinned EPW reader](https://github.com/LBNL-ETA/Radiance/blob/rad6R0P2/src/gen/loadEPW.c), and [official colordata syntax](https://radsite.lbl.gov/radiance/refer/ray.html#Colordata). The actual installed `reinhart.cal`, `rayinit.cal` and executable hashes must match `dependencies/radiance.json`.

Working set is sampled every 100 ms; short processes may have no sample. The scratch number is a completion observation, not a continuously measured peak, and these numbers are not production annual resource measurements.
