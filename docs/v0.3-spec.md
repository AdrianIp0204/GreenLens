# GreenLens v0.3 release contract

## Purpose, scope and retained behavior

Implement climate-based daylight studies, not a plan or visual prototype. GreenLens remains an international local-first offline-capable architect-facing application, with original branding and the v0.2 Rhino-inspired constrained modeling workspace. Retain native Windows, Rust/MSVC, Tauri 2, React/TypeScript/Three.js WebGL2, npm lockfile, Apache-2.0 original code, reviewed dependencies, shared Rust CLI/desktop services and directly supervised Radiance subprocesses. Rust owns authoritative geometry, units, scientific input validation, hashes, calculations, metrics and comparisons. No mandatory Python, Honeybee, cloud service, database or plugin marketplace.

Source remains in the authorized checkout. Build and active simulation caches use `%LOCALAPPDATA%/GreenLens`; engine acquisition remains separate. Compact immutable evidence belongs in portable project storage. Preserve historical v0.1/v0.2 specifications, failed checks, engine identities, hashes and run bytes. Static calculation retains its exact label: **Static daylight illuminance under a prescribed CIE standard overcast sky.** Old evidence inspection must not require annual executables. Recheck actual repository/authentication before public operations; inspect staged content and exclude private paths/data, credentials, engines and build outputs.

Only one rectangular room/window, optional fixed horizontal overhang and detached rectangular obstruction, neutral diffuse materials and simplified neutral glass. Annual studies support exactly 8,760 non-leap hourly intervals and at most 256 sensors; static studies retain the existing 10,000 sensor cap. No dynamic blinds, BSDF products, glare, thermal analysis, certification, arbitrary CAD/BIM, dynamic facade systems, CFD or optimization. Annual metrics are not sDA, ASE, LEED/BEAM criteria or certification. Later roadmap only: one-zone EnergyPlus with a thermal model, bounded IFC ingress, richer geometry and regional evidence consumers.

## Gate 1: versioned studies and weather

Introduce distinct versioned static, weather-selected-hour and annual study/result modes without altering legacy static serialization or fingerprints. Define supported historical schema/adapter dispatch explicitly. Keep adapters, local data providers and future assessment consumers separate; add a simple Rust local EPW provider, not a dynamic plugin system.

Validate EPW header/location metadata, fixed UTC offset, periods, ordered hourly interval timestamps, required irradiance/sky-model fields and missing sentinels. Reject leap, subhourly, multiyear, duplicate, incomplete, out-of-order and unsupported source conventions clearly. No missing required data becomes nighttime zero. Distinguish radiation accumulation (Wh/m² over an interval) from mean irradiance (W/m²). Document hour 1–24, interval-end labels, representative solar time, midnight rollover, longitude sign and local standard time; never apply OS timezone/DST. Typical-year source years do not imply one real calendar or weekday schedule.

Review source-specific irradiation timestamp/offset conventions. Require a documented supported interpretation/profile; never silently reinterpret incompatible files. Preserve original bytes/hash, citation, station coordinates/elevation/UTC offset, source-year information, normalization policy and licensing inside portable storage independent of the import path. Use original explicitly non-climatic synthetic fixtures and one rights-reviewed real full-year acceptance dataset (Hong Kong preferred if suitable). No network requirement during runtime.

Separate physical identity (geometry/materials, weather, sensor/time axes, sky method, engine/numerics) from metric identity (physical result plus schedule/thresholds). Schedule/threshold edits may derive new metrics without repeating transport but cannot display old metrics as current. View/selection/panel state affects neither identity.

## Gate 2: native climate calculation and metrics

Investigate pinned rfluxmtx/rcontrib/gendaymtx/dctimestep and select the smallest defensible fixed-glazing/shading matrix method. Explicit solar sources or validated direct-sun correction are mandatory: coarse redistribution of all direct sun over sky patches is not acceptable. Include indirect solar and ground radiance without double counting. Specify sky basis/orientation/order, ground treatment, sensor/time indexing, visible RGB units/lux conversion, solar geometry, interval representative time/horizon treatment, sampling/seeds, engine/adapter/executable/library hashes and exact arguments.

Choose one canonical weather-to-sky route from inspected source. Direct EPW versus WEA may differ in dew point/luminous efficacy; compare direct rays of the identical generated sky before characterizing differences between sky models. Do not demand unexplained gendaylit/gendaymtx equality. Complete results contain every one of 8,760 intervals, including explicit validated nighttime zero values; selected-hour and annual inspection identify actual weather interval and method.

Rust metrics use occupancy weights `w_t` (finite 0–1, nonempty denominator):

- `DA_T = 100 * sum(w_t * [E_t >= T]) / sum(w_t)`.
- `cDA_T = 100 * sum(w_t * min(E_t/T, 1)) / sum(w_t)`.
- `UDI_[L,U] = 100 * sum(w_t * [L <= E_t <= U]) / sum(w_t)`.
- Underlit is `E_t < L`; overlit is `E_t > U`.

Defaults T=300 lx, L=100 lx, U=3,000 lx are editable study conventions. Default daily occupied interval is 08:00–18:00 local standard time: 3,650 hourly intervals. Support a daily interval and explicit 8,760-element mask, including fractional weights; reject empty occupancy. Occupied nighttime remains in the denominator. Never infer weekdays from stitched years. Report per-sensor metrics and labeled sensor summaries; an unweighted fraction of sensors is not floor-area percentage. Extend CLI with weather inspect/import, study run, inspect, compare, export and replay via the shared service.

## Gate 3: storage, compatibility and verification

Use bounded versioned chunks with explicit shape, precision, ordering, units and checksums; stream processing and bounded slices across Tauri, no giant JSON matrices or unbounded tables. Retain archive limits: 5,000 entries, 64 MiB per entry, 256 MiB total uncompressed, safe unique relative paths. Preflight resource/package sizes and offer explicit run selection. Every successful export must pass its reader. Regenerable matrices/octrees remain scratch; retain compact original weather, normalized inputs, raw-output representation, results, recipes, provenance/logs/checksums sufficient to inspect/replay without original paths. Never execute imported commands.

Comparison requires compatible weather, time axis, occupancy/thresholds, sensors, sky method and numerical settings. Window/glazing/overhang differences are documented; incompatible comparisons reject without resampling. Hourly views share lux scale; annual metric deltas use percentage points. Explicit historical pairs expose run IDs and differences from current models/studies.

All v0.1 science thresholds remain unchanged. New acceptance tolerances are frozen before tuning:

| Check | Required tolerance |
| --- | --- |
| Identical-recipe replay | Every illuminance within max(0.5 lx, 0.5% of reference) |
| Analytical exterior same-sky normalization | Within 1% |
| Matched-sky selected-hour fixtures | Every sensor within max(5 lx, 5% of reference) |
| Full-year shipping/reference DA, cDA and each UDI band | Within 2 percentage points per sensor |
| Metric arithmetic | Within 1e-9 percentage points; UDI partition sums to 100% within same tolerance |

Cover strict timestamps/hour24/timezone/longitude/radiation units/missing/unsupported calendars; hand-calculated metric boundaries/partial occupancy/nighttime; matrix shape/order and independent small multiplication; same-recipe adapter/direct agreement; independent uniform-sky/solar-direction/unblocked-blocked beam/aperture-shadow fixtures; matched-sky high-quality tracing; full annual convergence and full A/B; legacy immutable inspection/replay; malformed/truncated/nonfinite outputs, nonzero exits, cancellation and resource limits.

Matched-sky checks use at least 12 documented daylight intervals across seasons, morning/noon/evening and clear/mixed/overcast conditions, for both A and B, plus separately identified shadow-edge cases. Predeclare selection and retain all failures; do not discard difficult cases or loosen thresholds. Investigate basis, sampling, sky consistency or sun method. Analytical fixtures establish limited behavior, not general real-building validation.

Only successful required exits, finite valid output, complete provenance and exact expected sensor/time shape permit finalization. Cancellation/shutdown terminate the Windows process tree and never promote partial runs.

Missing required native evidence keeps acceptance incomplete. Record hardware context, wall time, peak memory, scratch/package sizes, commits/engine IDs/shapes. No benchmark or validation claim without execution.

Update installation/launch/reproduction commands, artifacts and progress; inspect logical commits, verify actual remote/account, push scoped changes and check CI. Final report is self-contained with implemented/verified/unverified/blocked status, limitations, exact commands/artifact paths/repository. Stop at this bounded release.
