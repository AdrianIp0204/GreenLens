# v0.3 weather provider and reviewed source

The local Rust EPW provider is independent of the static model and does not use a network service, OS timezone or daylight-saving rules. Its explicit source profile is a scientific input, not a display preference. The original file remains authoritative; importing it must retain its exact bytes and SHA-256 alongside normalized engine input, source attribution and the recorded interpretation. Parsing an EPW is not validation of the weather measurements or reanalysis.

## Supported input contract

`weather::parse_epw(original, profile)` accepts ASCII/UTF-8, at most 16 MiB, exactly eight ordered headers and 8,760 ordered hourly records. It rejects partial, leap-day, subhourly, duplicate, reordered and actual multiyear axes. Each record has 35 fields. `DATA PERIODS` must declare one hourly period, January 1 through December 31 without year-qualified dates. Source-year labels may differ across a typical year; they remain provenance and never define weekdays. The eight original headers are retained. Non-calculation ancillary headers are not certification or design-condition inputs.

Location uses latitude north-positive, longitude east-positive, fixed UTC offset in whole minutes within -12 through +12 hours, and elevation >= -1,000 and <9,999.9 m. The pinned Radiance reader rejects offsets above +12, so those otherwise valid international locations are currently unsupported; no silent 24-hour shift is applied. Header numeric omissions are rejected rather than defaulted. Unknown textual station metadata must have an explicit marker. A period's weekday label and any holiday/DST metadata are retained but ignored for calculations and occupancy; nonzero holiday/DST metadata produces a warning.

Required daylight fields are DNI, DHI and GHI hourly accumulations in Wh/m², and dew point in °C. Radiation must be finite, >=0 and <9,999; dew point must be finite, >-70 and <70. Missing sentinels fail even for a dark interval. All other numeric fields must be lexical finite values so the engine cannot silently stop parsing. Their missing sentinels remain unchanged; they are not filled or used as daylight inputs. Negative unused infrared and out-of-range unused wind are reported. A GHI consistency warning is raised when DHI exceeds GHI by >0.1 Wh/m² or positive GHI >0.1 accompanies zero DNI and DHI; no values are repaired. Zero DNI/DHI is reported as **zero solar input**, not automatically as proof that the sun is below the horizon.

The underlying field order, radiation accumulation units, missing sentinels and hour 1–24 convention are documented in the [official EnergyPlus EPW dictionary](https://energyplus.readthedocs.io/en/stable/auxiliary-programs/auxiliary-programs.html#energyplus-weather-file-epw-data-dictionary). GreenLens deliberately accepts a narrower calendar/interval subset than EnergyPlus. This provider does not import an EnergyPlus runtime or perform energy analysis.

## Time profiles and normalization

| Explicit profile | Input convention | Versioned interpretation |
| --- | --- | --- |
| `epw_hour_ending` | Hour 1–24, minute 60; importer asserts hourly local-standard accumulations represented at their midpoint. An explicit irradiation offset, if present, must be -0.5 h relative to interval end. | `greenlens.epw_hour_ending_midpoint.v1` |
| `pvgis_tmy` | Reviewed PVGIS hourly EPW minute 0 marker, with explicit `Irradiance Time Offset (h):-0.5` in a comment header. Other offsets are rejected. | `greenlens.pvgis_tmy_epw_midpoint.v1` |

There is no guessed/default source profile. Selecting the generic profile asserts the source follows that convention; GreenLens cannot infer undocumented producer transformations. PVGIS satellite series with another representative offset are currently unsupported rather than shifted silently. The provider recognizes the documented irradiation-offset declaration and rejects malformed, duplicate or incompatible declarations.

For interval index `i`, local start/end/representative minutes are `60*i`, `60*(i+1)`, `60*i+30`. UTC-axis minutes subtract the fixed location offset. Signed UTC values are not wrapped: January 1's first local interval may lie in the previous UTC day, and December 31 hour 24 ends at the next local midnight. No actual calendar year is invented. A 1-hour accumulation divided by 1 hour has the same numerical value in mean W/m²; this is not a conversion from solar irradiance to lux.

The [JRC PVGIS TMY documentation](https://joint-research-centre.ec.europa.eu/photovoltaic-geographical-information-system-pvgis/using-pvgis-5/pvgis-5-tools/pvgis-typical-meteorological-year-tmy-generator_en) distinguishes UTC-labelled CSV/JSON from local-time EPW and describes the additional interval-end label and irradiation offset. In the acquired ERA5 files, JSON's +0.5 h and EPW's -0.5 h therefore identify the same hourly midpoint, not different timezones. The inspected pinned [Radiance loadEPW implementation](https://raw.githubusercontent.com/LBNL-ETA/Radiance/rad6R0P2/src/gen/loadEPW.c) uses `(hour-1)+0.5` for hourly records and does not use the EPW minute field in that case. Its solar axis uses month/day, while [gendaymtx](https://raw.githubusercontent.com/LBNL-ETA/Radiance/rad6R0P2/src/gen/gendaymtx.c) consumes the dew-point history. The canonical route keeps dew point instead of replacing it with a WEA/default value.

Canonical engine input removes any UTF-8 BOM, trims CSV padding, uses LF and writes minute 60. It also changes recognized `HOLIDAYS/DAYLIGHT SAVING` to `HOLIDAYS/DAYLIGHT SAVINGS`, the spelling required by the pinned native reader. All 35-field source values and source years remain present. The original headers are separately preserved unchanged. A first raw-PVGIS native attempt failed at this header; the failed experiment is retained, and canonical execution must be verified separately.

The pinned reader's fixed buffers impose additional explicit rejection limits: normalized lines <=1,022 bytes; city, region, country, source, period name and uncertainty flags <=63 bytes; station <=15 bytes. Numeric fields must remain finite in its single-precision representation; nonzero required radiation that would underflow to zero is rejected. No text is truncated. `original_sha256`, `normalized_sha256`, `time_axis_sha256` and the interpretation version form the study's weather binding. Original line endings/bytes affect the original hash; presentation does not. Serialized metadata is not trusted as proof of validation: storage/import must reparse original bytes and verify identities.

## Rights-reviewed real acceptance source

The selected source is a **PVGIS 5.3 ERA5 typical meteorological year at 22.30°N, 114.17°E near Hong Kong**, generated using 2005–2023 source years with PVGIS terrain-horizon masking disabled. It is gridded reanalysis-derived typical weather, not measurements at a named Hong Kong station, a forecast or a record for one actual year. The original LOCATION city/country/station fields say `unknown`; they are retained. The original declares elevation 18 m and UTC+8.

Primary rights review completed 2026-10-11:

- The [JRC dataset catalogue](https://data.jrc.ec.europa.eu/dataset/jrc-tmy-tmy-download-service) expressly authorizes reuse with source attribution under the European Commission reuse notice and describes EPW output.
- The [PVGIS-specific usage conditions](https://joint-research-centre.ec.europa.eu/photovoltaic-geographical-information-system-pvgis/general-information/usage-conditions-data-protection_en) place no use restriction on the supplied information. The [Commission copyright notice](https://commission.europa.eu/legal-notice_en) states its general CC BY 4.0 policy, requires credit/change identification, and excludes third-party rights and branding. The dataset inventory conservatively records the specific EC reuse notice rather than asserting that every EPW source is CC BY.
- Underlying [ERA5 catalogue licensing](https://cds.climate.copernicus.eu/datasets/reanalysis-era5-single-levels?tab=overview) is CC-BY; the [ECMWF citation guidance](https://confluence.ecmwf.int/spaces/CKB/pages/222493847/Use+Case+2+ERA5+hourly+data+on+single+levels+from+1940+to+present) requires visible Copernicus attribution. Retain the dataset-specific notice in `third-party/weather/PVGIS-ERA5-NOTICE.txt` with redistributed original/normalized data and reports.

The reviewed redistribution decision applies to these PVGIS-generated data with attribution and normalization/change disclosure. It does not grant rights in arbitrary EPWs, standards, logos, names, maps or PVGIS software. No PVGIS software is incorporated. OneBuilding weather files were considered, but a third-party CC-BY claim was insufficient without a matching primary grant; no OneBuilding data is used.

Exact acquisition URL and digest are in `dependencies/weather.json`. Initial acquisition may use the network; normal import/calculation/reopen/replay does not. Upstream output may change, so a new response must match the pinned digest or be reviewed as a different dataset. The EPW original is 1,863,014 bytes, SHA-256 `60719262a01e8827e8984537800f97f508ab4ae5ae8abc55fce571893c55b2d8`. The 12 source years are 2014, 2018, 2005, 2011, 2011, 2021, 2011, 2022, 2012, 2014, 2017 and 2007.

Following independent review of the primary grants, the exact original is retained at `examples/weather/pvgis-hong-kong-tmy-2005-2023.epw`, with `pvgis-hong-kong.source.json` for portable CLI import. The byte count and digest were checked after copying; a private-path/credential-term scan found no matches. Distribution must retain the source record and weather notice.

Read-only inspection observed 8,760 rows of 35 fields; all required daylight values are finite/in-range. It also found 3,853 negative unused infrared values and two negative unused wind values. These remain visible warnings; no thermal/wind suitability is claimed. For a separate JSON response shifted by the documented UTC+8 local-time relationship, all GHI/DHI values matched exactly, but 359 DNI values differed by up to 10.99 W/m². This comparison is retained as a source-format discrepancy, not treated as integration success. The EPW values alone are authoritative; JSON values are never substituted.

## Provider verification

`weather::synthetic_epw()` supplies an original, explicitly non-climatic repeated day for portable examples and service tests. It is validated by the same parser before use. `crates/greenlens-core/tests/weather.rs` also generates independent non-climatic fixtures and tests complete ordering, hour 24 and UTC rollover, positive/negative/fractional offsets, distinct source years, profiles, hash/normalization identity, required missing/nonfinite inputs, unsupported formats, metadata warnings and resource/engine-buffer limits. The explicit real-source test is ignored by ordinary local tests because it requires the separately acquired original; an ignored test is not acceptance evidence. When explicitly invoked, absence of the file or a different digest fails. Required release verification must invoke it or the equivalent required service acceptance, never count an optional skip.

```powershell
. ./scripts/dev-env.ps1
cargo test -p greenlens-core --locked --offline
$env:GREENLENS_ACCEPTANCE_EPW = Join-Path (Get-Location) 'examples/weather/pvgis-hong-kong-tmy-2005-2023.epw'
cargo test -p greenlens-core --test weather --locked --offline reviewed_real_hong_kong_pvgis_full_year -- --ignored
./scripts/weather-verification.ps1 -Cli (Join-Path $env:CARGO_TARGET_DIR 'debug/greenlens.exe')
```

This record covers weather parsing and source review. It does not establish full-year simulation, installed desktop or annual scientific acceptance; those require separate executed evidence.

Observed on native Windows 2026-10-11: the provider after native-reader hardening passed 11 synthetic checks and the explicitly invoked real 8,760-record check (12 passed, zero skipped/failed), followed by strict core Clippy. Earlier in the same turn all 15 legacy core and six new study tests passed. Exact commands, dirty source identity and tested file digests are in `v0.3-weather-evidence.json`.

A subsequent review added rejection of two irradiation-offset declarations on the same comment line. The first required CLI regression correctly failed because its binary predated that source repair; that failed attempt remains recorded. After rebuilding, the complete required weather CLI script passed: 8,760-record inspection/import, byte-identical relocation, reopening with both original import paths unavailable, retained attribution, and rejection of missing files, checksum corruption, unsupported offsets and conflicting same-line offsets. This establishes portable provider behavior without an engine or network.

The final core weather suite then passed all 12 tests again, including the real file and same-line declaration cases, with zero skips and strict Clippy passing. Six runner service tests passed within the shared owner's 29-test runner library suite: portable reopening without original paths, resealed forged derived metadata, resealed false binding, altered normalized bytes, invalid attribution/local source URLs, and preservation of existing destination files/directories/assets. These tests deliberately reseal altered files to check semantic revalidation beyond checksums. All original failed observations and exact later source/binary identities remain in the evidence record.
