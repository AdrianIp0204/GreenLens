# v0.4 energy workflow

This guide describes the implemented Windows desktop and shared CLI services. It is not a qualification record. See the [method](v0.4-energy-method.md), [contracts](v0.4-energy-contracts.md), [specification](v0.4-energy-spec.md) and [progress ledger](progress.md) for assumptions, evidence and unresolved acceptance. An execution completing, retained files passing integrity checks, inputs matching a snapshot and scientific qualification are separate statements.

## Dependencies and original example

EnergyPlus and Typst are separate pinned installations, outside source and project folders. The [EnergyPlus inventory](../dependencies/energyplus.json) and [Typst inventory](../dependencies/typst.json) bind their versions, resources and licenses. From a source checkout, the installation helpers are:

```powershell
pwsh -File scripts/install-energyplus.ps1
pwsh -File scripts/install-typst.ps1
```

These helpers may download the pinned dependencies during setup. Subsequent local runs and report generation use the retained installation. A missing or altered dependency is an error; there is no fabricated-result fallback. The desktop dependency fields accept the installed package directory. Leave them blank to use the pinned default installation.

Select **Energy** in the desktop discipline switch, then **Create original four-zone example…**, or **New** in an existing energy workspace. Choose a new project directory. Creating the example writes original synthetic model and weather data; it does not run EnergyPlus. The [example description](../examples/energy/README.md) identifies its synthetic location, calendar, schedules, sizing and performance curves. It is neither a measured building nor a climatic weather year.

The bounded model supports one to eight rectangular zones in at most two storeys, reciprocal full-face interzone adjacency, layered opaque constructions, simplified glazing, fixed overhangs and box shading. Cooling uses explicit single-speed DX systems, continuous supply fans while available, and separately scheduled balanced intake/exhaust ventilation. Heating, humidity control, heat recovery and central plant are outside this route.

## Desktop editing and document protection

Choose **Baseline A** or **Proposed B**, then a zone. **Model** shows accepted, Rust-validated geometry. Drag to orbit, right-drag to pan, click a zone to select it, and use **Fit model** for extents. Camera navigation does not edit scientific inputs. The daylight workspace remains a separate discipline.

The inspector edits a draft until **Validate and apply** succeeds:

- **Zone:** people, lighting and equipment densities; infiltration; schedule assignments.
- **Envelope:** surface constructions, window position and dimensions, glazing, overhang projection, shared material thickness/conductivity and glazing properties. Shared materials affect every referencing construction.
- **Systems:** rated coil capacity/COP/SHR/airflow, deadband, availability/setpoint schedules, supply-fan inputs and balanced ventilation flow/fan/schedule.
- **Schedules:** 144 explicit ten-minute values for weekday, Saturday and Sunday. Values and schedule roles are validated by Rust.
- **Advanced:** the complete model/study JSON, including zone topology, dimensions, reciprocal boundaries, construction layers, explicit curves, heat fractions, citations, holiday overrides and calendar. This is data, not executable code.

HVAC availability is binary in operation: zero is off and a positive schedule value makes the unit available. A fractional value does not proportionally reduce coil capacity or continuous supply-fan power. The independently scheduled ventilation fraction has its own meaning.

One accepted edit creates one undo entry. A rejected edit leaves the accepted document and history unchanged. **Discard draft** restores accepted inspector values. **Lock thermal inputs** disables thermal edits and their undo/redo; report metadata remains separate. There is no implicit partial geometry override around locked dependent inputs.

**Save**, **Save As**, **Undo**, **Redo**, **Open**, **New** and **Close** use the shared document lifecycle. New/Open/Close protect unsaved changes, active work and completed unsaved evidence with Save/Discard/Cancel. Save As copies referenced immutable evidence and weather, rather than relying on an old absolute folder. Undo restores inputs while retaining subsequently saved runs, weather and attachments.

While Energy is active, Ctrl+N creates an energy example; Ctrl+O opens; Ctrl+S saves; Ctrl+Shift+S saves a copy; Ctrl+Z/Ctrl+Shift+Z or Ctrl+Y traverse history. Focused text fields keep native text editing shortcuts. Daylight command-repeat, Delete and F8/F9 are not dispatched as thermal actions. Inspector drafts are not accepted scientific changes until applied.

## Weather, calculation and results

**Weather** imports an original EPW with citation, source URL if present, license and redistribution-rights note. Mark artificial data as synthetic. Thermal admission requires one complete non-leap hourly year and explicit thermal weather fields; a weather file admitted for daylight can still fail thermal admission. Missing infrared, wind or other required fields are rejected rather than silently derived.

The study uses fixed local standard time, an explicit start weekday, holiday calendar and UTC offset. There is no operating-system timezone or daylight-saving substitution. The optional location checkbox explicitly assigns both model sites from the admitted weather; the calendar offset must already match. Edit the calendar in Advanced before import when necessary.

**Run annual EnergyPlus** saves accepted inputs and starts the selected alternative through the shared Rust job service. **Cancel** requests process-tree cancellation. A failed or cancelled calculation does not become a completed immutable run. Job messages remain available in the left sidebar.

**Results** offers retained snapshots. Rust chooses the newest compatible snapshot by completion time; a later incompatible run does not hide a compatible one after undo. An explicitly selected historical snapshot remains inspectable. Each result carries execution, evidence-integrity, input/result-currency and scientific-assessment information. Pending or failed reads do not display a successful integrity or scientific attestation.

Results include annual/monthly facility electricity, disjoint end uses, gross-area EUI, coincident ten-minute facility peak and its simultaneous end-use contributions, occupied cooling-unmet hours, reconciliation and native diagnostics. The scheduled cooling setpoint used for comfort is distinct from the operative native thermostat output. Missing carbon factors remain missing rather than producing zero emissions.

**Series** reads at most 144 retained intervals per request. Enter a whole interval index within the retained year. The default plot/table displays Rust-derived ten-minute facility demand in kW and local interval-end labels. Five-minute sensitivity rows are combined in Rust before demand conversion. Raw native channels remain separately selectable with their actual units. The displayed integrity scope identifies the requested-chunk check; it does not claim each small read reparses the whole year.

**Compare** selects retained A and B separately and displays both assessments even when a pair is incompatible. Comparisons disclose service/input changes and lighting-service equivalence. Lower lighting power alone is not evidence of equivalent illumination. Energy and demand values, savings, zero-denominator behavior and display rounding come from Rust.

## Reports and optional evidence

In **Evidence**, supply a sourced carbon-factor JSON or `null`, and optionally a lighting-service-evidence statement. Report settings affect derived outputs rather than rewriting immutable simulation runs. No regional carbon factor is selected automatically. The supplied [synthetic factor](../examples/carbon/synthetic-fixture.json) is deliberately fictional and must not be presented as a real accounting factor.

PDF/PNG/JPEG attachments require a caption and redistribution-rights statement. Imported files bind the current model identity, remain inert and are excluded from reports/exports by default. Select each inclusion checkbox explicitly. Save As preserves retained attachment bytes; exports exclude unselected private metadata and files. A changed model may make an attachment inapplicable rather than silently relabeling it.

In **Compare**, select both retained runs and choose **Generate assessment, inputs and performance reports…**. The normal route requires pinned Typst and produces the energy assessment, input appendix and performance comparison products from one authoritative Rust report dataset. The explicit **HTML/CSV/JSON/SVG only** option omits PDF/PNG. Choose a new report directory name in the native save dialog; the service creates that directory atomically. An existing directory is rejected, and existing results are not overwritten.

**Export portable A/B ZIP…** includes the selected immutable evidence, original weather, qualification supplement and report products, with bounded members and checksums. It requires Typst. Inspection validates package paths and hashes before reading evidence. Replay is a separate explicit engine operation; opening an export never executes commands supplied by that export. Report cancellation is available through **Cancel** while generation is active.

## Headless commands

The executable is `greenlens.exe`. Paths below are examples; use a fresh destination outside source. Commands share the same Rust services as the desktop. Creating, inspecting and reporting retained evidence are distinct from the explicit `run` and `replay` engine operations.

```powershell
greenlens.exe energy example "C:\Work\Thermal example"
greenlens.exe energy doctor
greenlens.exe energy run "C:\Work\Thermal example" --alternative A
greenlens.exe energy run "C:\Work\Thermal example" --alternative B
```

Use the resulting immutable run IDs as `A_RUN_ID` and `B_RUN_ID`:

```powershell
greenlens.exe energy inspect "C:\Work\Thermal example" A_RUN_ID
greenlens.exe energy rows "C:\Work\Thermal example" A_RUN_ID --start 0 --count 144
greenlens.exe energy compare "C:\Work\Thermal example" A_RUN_ID B_RUN_ID
greenlens.exe energy report "C:\Work\Thermal example" A_RUN_ID B_RUN_ID "C:\Work\Reports"
greenlens.exe energy report "C:\Work\Thermal example" A_RUN_ID B_RUN_ID "C:\Work\HTML reports" --html-only
greenlens.exe energy export "C:\Work\Thermal example" A_RUN_ID B_RUN_ID "C:\Work\energy-evidence.zip"
greenlens.exe energy package-inspect "C:\Work\energy-evidence.zip"
greenlens.exe energy replay "C:\Work\energy-evidence.zip"
```

`--engine-dir DIRECTORY` is supported by doctor/run/replay; report/export accept `--typst-dir DIRECTORY`. Ctrl+C requests cancellation of native calculation, replay or report generation. Inspection and package inspection do not start a simulation.

The complete model and study are JSON values under `project.json` → `energy.designs.A` or `.B`. Keep the model and study as separate files for these operations; do not pass the whole project JSON as a model:

```powershell
greenlens.exe energy validate model.json calendar.json
greenlens.exe energy configure "C:\Work\Thermal example" model.json study.json --alternative B
greenlens.exe energy weather-inspect original.epw
greenlens.exe energy weather-import original.epw "C:\Work\Weather asset" --source-record source.json
greenlens.exe energy weather-attach "C:\Work\Thermal example" "C:\Work\Weather asset" calendar.json --apply-location
greenlens.exe energy report-settings "C:\Work\Thermal example" --carbon-factor factor.json --lighting-service-evidence "Documented design evidence and its scope"
greenlens.exe energy attach "C:\Work\Thermal example" evidence.pdf --alternative A --caption "Model evidence" --rights "Original author; permission to redistribute"
```

`source.json` uses `citation`, nullable `source_url`, `license`, `rights_note` and `synthetic_non_climatic`. Omit `--apply-location` to require the existing model sites to match weather. Omitting a report-settings option clears its corresponding derived setting; it does not silently retain an older factor. Use `energy attachment-include "C:\Work\Thermal example" ATTACHMENT_ID --included true` to include an attachment, or `--included false` to exclude it. Review its model correspondence before export.

These commands describe implemented interfaces. Synthetic UI/report tests do not establish installed-desktop, EnergyPlus or scientific acceptance; those outcomes must be recorded separately with actual retained evidence.
