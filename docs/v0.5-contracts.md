# v0.5 workbench contracts

This document describes the additive implementation of the [bounded workbench specification](v0.5-spec.md). It does not certify completion of the [acceptance ledger](v0.5-acceptance.md). The [v0.4 thermal, weather, series and report contracts](v0.4-energy-contracts.md) remain the authority for retained energy evidence. Existing daylight contracts and failed scientific outcomes are unchanged.

## Ownership and identities

Rust owns accepted models, geometry, units, calendar expansion, typed comparisons, statistics, hashes and scientific assessment. `greenlens-core::energy` provides pure contracts; `greenlens-energyplus` owns supported native mappings; `greenlens-runner` provides persistence, orchestration and report services. CLI and Tauri call those services. React renders accepted geometry and bounded result projections, retains provisional text, and requests typed actions. Neither a local draft nor a package-provided command is an execution authority.

| Identity or state | Meaning and authority |
| --- | --- |
| Accepted design | Thermal model plus optional study; a successful Rust transaction changes only explicitly selected A/B targets |
| Physical input and method | Exact model, weather/calendar, complete numerical settings, engine and recognized recipe; schedules are physical inputs |
| Immutable run | Original snapshots, native process receipts, normalized output, totals and seals; later editing never rewrites it |
| Processing and comparison | Recognized processing contract and separately versioned derived comparison policy |
| Carbon and lighting-service evidence | Explicit report inputs; absence is disclosed rather than interpreted as zero or equivalence |
| Report presentation | Immutable base dataset identity plus explicit issue metadata, typed comparison, attachment decisions, selected profiles and template identity |
| Local drafts and display | Provisional editor text, cameras, selection, visibility and layout; excluded from physical inputs and immutable run hashes |
| Numerical sensitivity | Separately sealed declaration, reuse choices, execution receipts and assessment; no registry promotion |

Execution completion, evidence integrity, current-input relationship and exact-method scientific qualification remain separate axes. A bounded catalog reads checked metadata only; a full inspection/export checks complete retained evidence. Neither check establishes physical accuracy. Unknown user inputs or methods are unassessed. The compiled registry preserves known failures and grants limited qualification only to its exact listed scopes.

## Accepted edits, drafts and geometry

`EnergyWorkbench` is an optional `greenlens.energy-workbench.v1` project supplement. It holds per-design semantic locks, explicit pre-study calendars, optional report issue metadata and sensitivity references. A configured study's calendar is authoritative; its fallback calendar is not silently overwritten.

`energy/workbench.rs` defines `greenlens.thermal-transaction.v1`. Supported operations add, remove or resize rectangular zones, explicitly pair adjacent/stacked full faces, assign constructions/boundaries, and put/remove windows and detached box shading. A preview includes the base/candidate identities, affected semantic IDs, diagnostics and candidate model. Commit recomputes the preview against current inputs and locks; stale previews fail. Full topology validation runs before acceptance. There is no arbitrary CAD operation, hidden repair of the other design, or partial transaction after validation failure.

`energy_workbench::restore_designs` changes only requested model/study snapshots and enforces current locks. Runs, weather, report settings and later retained evidence survive undo/redo. `energy_design_copy::{preview,commit}` provides explicit A-to-B or B-to-A input copying. It copies no evidence, attachments, report metadata or lock state. Configured source studies carry their own calendar. An unconfigured source requires the destination's effective fallback calendar to match; otherwise the preview asks for explicit calendar alignment. This preserves a single design-history entry without a hidden calendar edit.

Rust builds `greenlens.thermal-scene.v1` polygons for zones, faces, openings, overhangs and detached shading. IDs are semantic and stable. Dependent geometry participates in lock checks: for example, changing a parent face or building rotation affects its window/overhang snapshot. Visibility never excludes an object from simulation. The frontend's `greenlens.thermal-presentation.v1` store keeps four independent cameras, active/maximized view, selected/hidden/isolated IDs and bounded panel widths separately from portable scientific evidence.

Frontend thermal drafts use `greenlens.thermal-drafts.v1`, keyed by document/design; report-settings and issue-information drafts are document-specific. Structured fields retain incomplete numeric text and Advanced retains raw JSON. Apply validates through Rust and creates history only on success. Failed or stale Apply leaves the draft intact. A response may clear only the captured draft instance, never text entered while an asynchronous request was running. Apply/Discard/Cancel guards cover saving, calculation and document replacement. The recovery cache is bounded to 16 entries, 1 MiB per entry and 4 MiB total; a cache failure warns while preserving the in-window draft. Cached input remains untrusted and must be applied explicitly.

Guarded Apply treats all pending design, report-settings and issue-information drafts as one transaction. Every candidate is parsed first; existing Rust services then transform and validate a disposable project snapshot. Only complete success with unchanged captured drafts permits one accepted-state/history adoption. A later invalid draft, Rust rejection or newer text accepts none of the batch and clears none of its drafts. Undo/redo stores only the edited design/metadata fields and revalidates through those services, preserving later runs, weather and attachments. Individual inspector Apply remains a single-draft action.

Schedule blocks cover exactly 00:00–24:00 with ten-minute boundaries and no gaps/overlap. Rust expands 144 values without interpolation. Weekday, Saturday, Sunday and exact non-leap holiday profiles remain distinct. Calendar changes explicitly reconcile holiday profiles; copying a Sunday profile for a new holiday is a disclosed draft operation, not an engine default.

## Typed differences and preflight

`compare_thermal_inputs_v1` returns `greenlens.thermal-input-differences.v1` under policy `greenlens.thermal-service-comparison/1`. Each row has a typed object reference, exact field pointer, typed before/after values, unit, category and service effect. Detailed rows are bounded to 4,096; total counts, compatibility and service flags still account for every change. Truncation is explicit.

Supply/ventilation fan efficiency and pressure changes are equipment-design changes. Airflow, ventilation schedules, availability, occupancy and setpoints can change service. Identical declared service inputs do not prove measured service equivalence; reduced lighting power does not prove equal illumination. This new interpretation supplements historical comparison data instead of replacing its serialized semantics.

Core preflight reports the unchanged authoritative validator's first failure. A safely located cause links to an exact object/field; ambiguous failures remain model-level with an explicit coverage statement. Adapter preflight also checks the study, every DX rating, deterministic owned input generation and existing size limits. The existing supported rating is 19.44 °C indoor wet bulb and 35 °C outdoor dry bulb with the adapter's unchanged strict tolerance; there is no inferred rating conversion.

`energy_preflight::inputs` adds missing retained-weather references and a separate scientific-status explanation. `energy_preflight::dependencies` checks pinned EnergyPlus or Typst/font installations independently. Input readiness alone does not attest installed binaries, original weather bytes, successful execution or operating curve-domain applicability. Start repeats the relevant authoritative checks; the UI readiness label cannot bypass them.

Original strict thermal weather admission remains available. The separate dry-envelope profile has a distinct method/recipe identity, retains the specified original missing tokens, disables rain/snow surface effects and enforces an explicit native-object consumer restriction with monthly ground reflectance 0.2. It is not a silent repair of old weather. The [real-weather protocol](v0.5-real-weather-protocol.md) records that complete active-coil curve-domain observability remains blocked; no annual candidate was run under that protocol.

## Bounded result investigation and history

`energy/investigation.rs` defines `greenlens.energy-investigation.v1`. Requests select an exact local-standard time, a day, an explicit range, the retained facility-peak day, or the next occupied cooling-unmet interval. Dates use the retained non-leap calendar, not the operating-system timezone. A range is start-inclusive/end-exclusive; 24:00 is valid only as an exclusive endpoint. No date navigation wraps silently into another year.

Responses contain at most 1,008 common ten-minute intervals (seven days), requiring at most 2,016 five-minute source rows. Five-minute energies are summed in pairs before dividing by 600 seconds to produce kW. Native comfort samples remain unaveraged and use the existing strict temperature threshold. Next-unmet search scans the remaining finite year in bounded chunks, reports its scanned count and returns an exact bounded window or explicit absence. It does not force the user to advance through empty windows.

`energy_navigation::{query,pair}` uses immutable metadata and only requested/searched chunks. Pair navigation retains the existing complete method/weather/calendar/geometry/ledger compatibility checks, aligns both sides to the chosen anchor and supplies a Rust-derived shared demand scale. It does not weaken A/B compatibility to make a chart possible. `energy_catalog::catalog` returns at most 100 checked metadata rows in explicitly stated reverse-retention order, with retained name, UTC completion, input revision, method and all assessment axes. That order is not presented as completion-time order.

## Finite numerical sensitivity

Core `greenlens.energy-sensitivity-declaration.v1` fixes selected A and/or B targets, exact 10/5-minute studies and criteria. Runner `greenlens.energy-sensitivity-plan.v1` binds current accepted inputs and chooses the earliest UTC-completed exact input/method run, breaking ties by canonical run ID. Every reused run is fully reprocessed. Numerical outcome never chooses reuse. A plan is inspection data and does not start work.

`energy_sensitivity_workflow` retains `greenlens.energy-sensitivity-session.v1` under relative `energy-assessments/<id>` members. The portable reference binds immutable plan bytes and a chronological receipt hash chain. At most 32 sessions and 13 event receipts per session are admitted. One explicit step reserves a missing slot before using the application's existing single-job lifecycle; normal collection attaches successful evidence. A started-record failure stops the worker. Failed/cancelled/interrupted attempts stop that declaration and remain recorded; there is no automatic retry or competing supervisor.

The fixed case order is A10, B10, A5, B5 with unselected targets omitted. Annual facility electricity difference uses the five-minute denominator and a 1% limit. Peak uses aligned ten-minute bins, the finer-step denominator and a 3% limit. The existing 1% occupied cooling-unmet criterion at 0.2 °C applies to every conditioned zone in each declared run. Building-union comfort is diagnostic, not an invented gate. Missing evidence or any failed/cancelled receipt prevents successful completion; passing does not promote scientific qualification.

Open, Save As and export verify referenced sidecars, input/run/process identities and every collected-run seal. Source-less Save As cannot invent sidecars. Extra or missing receipts fail closed; the explicit CLI recovery path reconciles a valid interrupted metadata commit or records an unresolved attempt as interrupted. It does not rerun a case or delete evidence. Historical final assessment bytes remain unchanged when accepted inputs become stale; currentness is returned separately.

Portable A/B export selects the first retained finalized session matching the exact selected A10/B10 pair, irrespective of its pass/fail outcome. Its required five-minute runs may bring the package to four runs. Excluded session IDs and the selection policy are disclosed. Every reference is inspected before selection, including excluded references. Reports currently disclose no sensitivity assessment unless their report contract explicitly includes it; ZIP retention must not be described as report-level scientific endorsement.

## Reports, attachments and package trust

`EnergyReportWorkbenchData` (`greenlens.energy-workbench-report.v1`) embeds the unchanged `EnergyReportData` base and its hash. It adds validated title/revision/date/author/preparer/history, executive/technical profile selection, recomputed typed differences, attachment disposition summary and owned-template hash. Its derived identity changes when those presentation inputs change; physical/run identities do not. Blank optional names/dates remain absent. No approval or reviewer is inferred.

The runner renders the new profiles plus the retained input/performance product families from immutable snapshots. Rust supplies full-precision values and centralized display cells; templates do not recompute scientific totals. Selected attachments must be present, sealed and applicable to one selected model. Checked missing/invalid/inapplicable evidence blocks output. Unchecked private captions, paths and hashes are excluded; only bounded disposition counts enter the public supplement. Package inspection rederives the dataset and supplement binding rather than trusting an imported assessment.

All output uses existing bounded path/checksum readers. Shared scientific archives remain limited to 5,000 entries, 64 MiB per entry and 256 MiB total uncompressed. A successful package must fit both writer and reader. The separate offline documentation selection is capped at 16 MiB including its generated index, 2 MiB per document; it is not a simulation-storage allowance. Process deadlines, tree cancellation and final successful completion remain mandatory. Package data never supplies executable commands or report templates.

Final v0.5 clean-source CI, package, cold replay and installed workflow evidence are not established by this contract. See the [delivery guide](v0.5-delivery.md) for supported actions and the [acceptance ledger](v0.5-acceptance.md) for performed versus pending observations.
