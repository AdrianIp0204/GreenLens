# GreenLens v0.5 Professional Thermal Workbench

Implementation activated 2026-10-14. This is a bounded extension of the existing energy application, not a replacement simulator or acceptance of earlier unverified desktop behavior. The user must complete New Project, four-zone/two-storey modeling, input assignment, A/B simulation, investigation, numerical sensitivity and reporting without editing JSON. Historical specifications, raw runs, failed scientific checks and replay identities remain immutable.

## Platform, physics and identity boundaries

Keep native Windows Rust/MSVC, Tauri 2, React/TypeScript/Three.js WebGL2, npm lockfile, shared Rust CLI/desktop services and Apache-2.0 original code. Normal operation is offline. Source stays in the chosen checkout; builds and active jobs use per-user local GreenLens storage, with EnergyPlus and Typst/fonts separately installed. No mandatory Python, database, cloud, paid service or dynamic plugin system. Machine dependency paths belong only in local settings. Imported data never provides executable commands/templates.

Keep 1–8 rectangular zones, at most two storeys, full-face adjacency, existing cooling-only single-speed air-cooled DX/fan topology, and existing storage/resource limits. No VRF, plants, heating, DHW, lifts, arbitrary CAD/BIM, IFC/3DM, regional assessment rules, optimization or marketplace. The exhausted v0.3 climate-daylight qualification remains failed/unqualified and stopped. Preserve original energy thresholds and separate execution, integrity, currentness and exact-method scientific qualification. Unknown inputs/methods are unassessed; successful sensitivity does not confer the synthetic example's registry status.

Physical input, processing, comparison, carbon and report-presentation identities are distinct. Camera, selection, visibility and layout do not affect scientific hashes. New derived semantics must be versioned without rewriting old evidence. Shared archive bounds remain 5,000 entries, 64 MiB/entry and 256 MiB total uncompressed; bounded result queries remain authoritative.

## Gate 1 — editing safety and semantic repairs

Keep durable structured and Advanced JSON drafts keyed by document and design across panel, inspector, design and discipline navigation. Label accepted versus draft values. Section changes must never overwrite raw JSON. Resolve relevant drafts through Apply/Discard/Cancel before document replacement, destructive transitions, Save/Save As, or calculations that would use earlier accepted inputs. Failed Apply retains draft and leaves accepted state/history unchanged. Never auto-accept unvalidated data. Saving must not imply unapplied edits were saved. Preserve native text editing and one undo entry per accepted operation.

Persist thermal cameras, projection, selection and layout separately. Results/discipline/panel navigation cannot reset cameras; Fit is explicit or initial new-model framing. Test real editor/viewport components, not null replacements.

Comparisons expose typed object/field changes with baseline/proposed values, units and category. Ventilation flow and operating schedule are service; fan efficiency/pressure are design parameters. Efficiency-only changes must not claim reduced ventilation service. Occupancy, availability, flow and setpoint changes still surface service warnings. Shared preflight includes core and adapter restrictions, including supported DX rating conditions. Issues distinguish invalid input, missing dependency/evidence, warnings and unassessed science, with severity, object/field links and actionable messages.

New Energy Project accepts an explicit supported layout rather than only cloning the demonstration. Preview affected objects and invalid geometry before commit. Rust builds and validates complete atomic transactions, rejecting partial-face/dangling/overlapping topology. A/B geometry effects require an explicit target choice and preview; never silently repair the other design for comparability.

Provide structured layered construction/glazing editors with units, sources and shared-use impacts; supported DX/fan/curve/rating inputs; occupancy, lights, equipment, infiltration and ventilation; site, calendar weekday/holidays/fixed UTC offset; and carbon source/year/region/units/synthetic status. Synthetic presets disclose assumptions and do not represent validated products. Advanced JSON remains optional expert inspection.

Schedule editing provides time blocks, a plotted profile and exact editable table; weekday, weekend and holiday profiles; duplicate; role and units. Rust deterministically expands the existing ten-minute semantics. No invented interpolation or changed schedule rules.

## Gate 4 — results and numerical evidence

Primary result navigation uses local-standard date/time, previous/next day, ranges, each case's facility peak and occupied unmet intervals. Plots have numeric axes, units, legends, exact cursor values and accessible tables. A/B plots use explicit aligned timestamps and shared scales. Run lists show names, UTC execution times, design revisions and current/historical relationship. Rust owns queries/aggregation; IPC is bounded. Any reduction labels preserved extrema and cannot replace authoritative/exported values.

An explicit Check Numerical Sensitivity action declares exact eligible study/pair inputs and ten-/five-minute method identities. Reuse only matching integrity-checked retained runs; execute only missing declared runs. Retain every success/failure/resource receipt, align five-minute data to common ten-minute demand, and enforce <=1% annual electricity and <=3% facility peak plus existing <=1% occupied cooling-unmet at 0.2 C fixture criteria. No automatic tuning, favorable reruns, changed A/B compatibility or scientific registry promotion. The assessment is separately identified numerical sensitivity evidence.

Declare one real-weather demonstration before execution: rights-reviewed complete non-leap hourly EPW, strict thermal suitability, original bytes, sources and explicitly sourced nonconstant DX curves with domain/rating applicability. Hong Kong is preferred only where data and rights fit. Any newly justified derivation or unused-field policy has its own version and never silently repairs historical data. Freeze exact inputs, finite runs, stop conditions, criteria and resources before running; retain failures and limit claims to observed evidence.
