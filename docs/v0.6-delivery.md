## Implemented workflow

1. Open or create a supported energy document. Opening performs cheap manifest admission, resolves document/draft protections, then runs one cancellable verification with stage/run/byte feedback. Cancellation or a rejected candidate keeps the prior document and pending evidence. A checked snapshot shares numeric records within that open. Follow-on result/sensitivity requests now reuse private validated records only after rehashing their original evidence members. The optimized four-run regression confirms no repeated numeric passes; installed latency/performance acceptance remains open.
2. Choose **Reference → Prepare local GLB import**. Enter explicit scale, orientation/origin and conversion provenance, acknowledge the coordinate choices and choose a self-contained GLB through the native picker. Rust admits the bounded static-triangle subset, seals normalized geometry and publishes the accepted project only after verification. The original source and GLB stay external. Inspect the receipt's exclusions, units, bounds and unknown-north status; imported appearance does not establish thermal inputs.
3. Use the central four views and searchable reference/analytical hierarchy. Select, isolate, ghost or section the reference, measure two admitted vertices, and inspect mapping status. These display operations do not change simulation inclusion. Local named camera views are display state. **Add active view to report draft** captures an orthographic frame/section with exact reference/design bindings; review and save the scope in Rust before it becomes report input. Perspective views remain local.
4. Declare a partial-building, representative or demonstrably complete supported scope. Map revision-scoped occurrences to explicit zones, surfaces, windows, overhangs or context shading. Record exclusions, boundary consequences, source measurements, approximation differences and assumption sources/units/rationale. Missing values and unknown coverage remain visible. Reimport/model edits make old bindings stale rather than silently rebinding them. Whole-building scope is rejected unless its declared coverage and mappings meet the restricted contract; a bounding box is not architectural equivalence.
5. Build/review the analytical model through the existing geometry and Properties forms. Keep the one-to-eight-zone/two-storey/full-face-adjacency limits and cooling-only DX/fan topology. The single semantic object tree routes selection to Properties. Locks, guarded drafts, undo/redo and camera state remain separate from report/display metadata. **Readiness & settings** contains machine-local EnergyPlus/Typst paths and explicit checks; **Current job** exposes state/logs without a permanent extra sidebar.
6. Import rights-cleared energy weather and explicitly review calendar, site scenario, constructions, schedules, gains, ventilation and equipment assumptions. Unknown site information may use a disclosed illustrative location; it must not imply the private building's actual site. Preflight-valid unknown models can run with Unassessed scientific status. Privately declare the exact scope and finite A/B/sensitivity study before execution.
7. Run each accepted design through the existing annual service, inspect retained snapshots, dates/peaks/comfort and compatible comparisons, then use the declared sensitivity action. This continuation has not yet performed those runs for the private architecture. Passing execution or timestep sensitivity is not physical validation or qualification promotion.
8. Select retained A/B evidence, review report/scope/attachment readiness, and issue standalone reports or a portable package. All required admitted reference revisions/chunks are included in the architectural package; original proprietary sources and conversion GLBs are explicitly excluded. An analysis-only ZIP omitting required admitted assets is unsupported. A standalone report is not an architectural-source archive. Save As copies the complete admitted project, including required assets and immutable evidence.

The interface paths above are implemented, with component/shared-service checks where recorded. They are not a substitute for the complete installed Windows demonstration. The private source has not been decoded; no private mapping, annual result or model-derived report exists at this checkpoint.

## Launch and dependency setup

There is no new v0.6 installer to recommend yet. The existing installed executable can be launched as follows, but its version/source must be checked; launching a historical candidate does not test v0.6:

```powershell
& "$env:LOCALAPPDATA/Programs/GreenLens/greenlens-desktop.exe"
```

For development from the checkout, use one coordinated build owner. Preserve an existing open document before closing or upgrading its application. The source stays in the checkout; the environment script sets external build/cache locations.

```powershell
. ./scripts/dev-env.ps1
$env:CARGO_BUILD_JOBS = '1'
Push-Location apps/desktop
npm ci
npm run tauri -- dev
Pop-Location
```

This starts a development server and cannot satisfy installed acceptance. Native Windows/MSVC, WebView2 and the Visual C++ runtime requirements remain in [installation](installation.md). Engines and renderer/fonts remain separately installed:

```powershell
pwsh -File scripts/install-energyplus.ps1
pwsh -File scripts/install-typst.ps1
```

Initial acquisition may use the network. Ordinary reference intake, modeling, retained inspection, calculations and reporting are local. Retained inspection/report reconstruction needs neither EnergyPlus nor original external source paths. PDF/PNG generation requires the audited Typst/fonts; real simulation/replay requires the compatible EnergyPlus. Explicit HTML-only output does not invoke either engine or Typst. No SketchUp SDK, installed DLL borrowing, automatic sign-in, online conversion or direct SKP reader is part of GreenLens; see the [intake/license review](v0.6-intake-licenses.md).

## Current shared CLI entry points

These commands are checked against the current command definitions, not an assertion that a final release artifact exists. From the configured checkout, a build owner can produce a CLI in external build storage:

```powershell
. ./scripts/dev-env.ps1
$env:CARGO_BUILD_JOBS = '1'
cargo build --locked --release -p greenlens-cli
$cli = Join-Path $env:CARGO_TARGET_DIR 'release/greenlens.exe'
& $cli --version
& $cli reference --help
& $cli energy --help
```

Create a new synthetic example, or set `$project` to an existing portable document. Never use this synthetic success as private-case acceptance. Destinations must be new where the command requires creation.

```powershell
$project = Join-Path $env:LOCALAPPDATA 'GreenLens/projects/architectural-example'
& $cli energy example $project
& $cli open $project --admission-only
& $cli open $project
```

Admission explicitly reports that evidence has not been checked. Full open emits progress on stderr and a verification receipt on stdout. Receipt pass counts and durations describe that actual operation; an absent receipt is not a verified result.

After a lawful local export, use actual local paths in the following variables. Do not put private paths or contents in public scripts/logs:

```powershell
# $glb is a self-contained local GLB; $options is an optional data-only JSON file.
& $cli reference import $project $glb
# With explicit scale, transform and conversion choices:
& $cli reference import $project $glb --options $options
& $cli reference inspect $project
& $cli reference scope-context $project
# $scope is a data-only declaration prepared against exact current identities.
& $cli reference scope-assess $project $scope
& $cli reference scope-apply $project $scope
```

Choose one import command; invoking both imports twice. Default import options use the documented GLB metre/Y-up conversion without inferring north or dimensions. The CLI's JSON options/scope interfaces are for advanced use; the desktop exposes forms. Scope validation never executes imported commands. Refer to [reference/scope contracts](v0.6-reference-contracts.md) and the versioned schemas for fields and bounds.

The existing thermal commands continue to use shared Rust services:

```powershell
& $cli energy doctor
& $cli energy preflight $project --alternative A
& $cli energy input-differences $project
# These commands start real annual calculations; use only after declaring inputs.
& $cli energy run $project --alternative A
& $cli energy run $project --alternative B
# Set $a and $b to the exact returned retained run IDs.
& $cli energy inspect $project $a
& $cli energy compare $project $a $b
& $cli energy rows $project $b --start 0 --count 144
```

Weather admission and the finite sensitivity sequence remain documented in the [v0.5 CLI guide](v0.5-delivery.md#shared-cli-commands). `energy sensitivity step` executes at most one declared missing case; it does not tune or loop until passing. The unchanged limits are 1% annual electricity, 3% aligned ten-minute facility peak and the original comfort criterion. A stopped historical protocol is not restarted by this guide.

For new output destinations and an exact selected retained pair:

```powershell
& $cli energy report $project $a $b "$project-reports"
& $cli energy report $project $a $b "$project-html" --html-only
& $cli energy export $project $a $b "$project-evidence.zip"
& $cli energy package-inspect "$project-evidence.zip"
& $cli copy $project "$project-copy"
# Separate real-engine reproduction, after integrity checking:
& $cli energy replay "$project-evidence.zip"
```

Reports/export accept `--typst-dir`; execution/replay accepts `--engine-dir`. Package inspection is engine-free and validates paths, seals, dimensions and recognized report bindings. Replay uses compiled recognized recipes, never commands supplied in the archive. All successful packages retain the unchanged 5,000-entry, 64 MiB-per-entry and 256 MiB-uncompressed limits.
