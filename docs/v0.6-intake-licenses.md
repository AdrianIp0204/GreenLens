# Architectural intake: conversion and dependency review

Reviewed 2026-10-15. This record separates a documented conversion route, the application's current availability, actual private conversion evidence, and permission to distribute software. It contains no private source identity, geometry, account information or machine configuration.

## Adopted boundary

The v0.6 intake boundary is local GLB 2.0 data admitted by GreenLens. SketchUp and its SDK are not GreenLens dependencies, are not included in packages, and are not invoked by imported recipes. Original GreenLens code and synthetic fixtures remain Apache-2.0. An imported model and its textures retain their own rights; the glTF format does not grant permission to redistribute those contents.

Conversion is a separately licensed local operation. GreenLens does not upload models to converters or cloud services, automate authentication, purchase subscriptions, extract installed SDK DLLs, or infer a license from an installed executable. Direct SKP support is not adopted for this release.

## Documented local export route

Official SketchUp help documents exporting through **File > Export > 3D Model**, choosing **GLTF Binary File (*.glb)** and a local destination. The export must leave the original source unchanged. Record the actual application version, export settings, warnings, source/output hashes and subsequent dimension checks in the private conversion receipt. The help page describes capabilities, not this project's conversion outcome. [SketchUp GLB export](https://help.sketchup.com/en/sketchup/working-gltf-files)

At this review checkpoint the native application had reached a usable welcome screen. This supersedes an earlier sign-in-gated availability observation; it is not proof that the private geometry has been opened or exported. Actual conversion and geometric admission remain separate acceptance evidence. If sign-in or entitlement later blocks export, the minimum intervention is the assigned user signing in with an existing entitled account, or providing a lawful local GLB export. No new subscription is assumed. Official guidance identifies sign-in as the means of accessing the assigned subscription seat. [SketchUp sign-in guidance](https://help.sketchup.com/en/logging-in-sketchup)

## SDK route reviewed but not adopted

The official C SDK overview describes standalone reading and writing of SKP files and directs developers to request SDK access. The C API documentation supplies technical usage details. These statements establish capability, not a license to distribute an SDK-based GreenLens converter. [SDK overview](https://developer.trimble.com/docs/sketchup/tools/sdk/), [C API documentation](https://extensions.sketchup.com/developers/sketchup_c_api/sketchup/index.html)

The current official Trimble Developer Terms were retrieved on the review date: version 2.1, updated June 26, 2026. Section 2.7 restricts development and distribution. Its SketchUp extension exception requires an active product license and excludes integrations that embed SketchUp files or functionality in a third-party application. The terms also incorporate applicable supplemental developer terms. This review established no separate distribution approval or applicable SDK-package supplemental agreement for GreenLens. Consequently neither SDK integration nor SDK redistribution is approved by this record. A future proposal requires review of the exact acquired package, its complete terms, supplemental agreement and intended distribution. [Trimble Developer Terms](https://www.trimble.com/en/legal/developer-terms)

No SDK was downloaded, linked, extracted or copied during this review. Existing scientific-engine and renderer dependencies keep their separately reviewed installation and distribution boundaries in [dependencies](dependencies.md).

## Neutral format and interaction references

The official glTF 2.0 specification supplies the metre units, right-handed Y-up convention, index-based references and transform rules used to define admission. Names are display labels rather than unique identities. Mesh instances require distinct occurrences. Local transforms compose in translation/rotation/scale order, and nodes form strict trees; bounds and measurements must use complete composed transforms. Required unsupported extensions must be rejected explicitly. GreenLens's supported static subset, resource limits and declared exclusions belong in its own import contract; support for glTF does not imply support for every extension, animation or material feature. [glTF 2.0 specification](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html)

McNeel's official documentation informs bounded workspace behavior: grouped commands, command prompt/history, focused value entry, viewport-title activation and maximize/restore, side panels, and coordinate/unit feedback. GreenLens uses original assets and implementation and makes no Rhino feature-parity claim. [Rhino window documentation](https://docs.mcneel.com/rhino/8/help/en-us/user_interface/rhino_window.htm)

## Evidence limits

Documentation retrieval and an available application are not private-case intake acceptance. The private case still needs actual local conversion, original-byte preservation, admitted geometry, source-to-analysis reconciliation and installed workflow observations. Any unsupported geometry or unresolved rights must remain explicit. Synthetic importer tests cannot substitute for that private evidence.
