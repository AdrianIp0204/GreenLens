# Architectural reference and analysis-scope contracts

The v0.6 supplement is additive. `ReferenceModel` represents admitted inert geometry; `ArchitecturalScope` records a reviewed relationship to separately validated thermal inputs. Neither modifies `ThermalModel`, physical simulation hashes, retained run bytes, historical replay recipes, or scientific qualification. An import or a current mapping does not establish analytical equivalence.

## Reference boundary

`greenlens.reference-model.v1`, importer `greenlens.glb-static-triangles/1`, binds original GLB bytes, import options, selected scene, occurrence paths, transformed triangles, materials and normalized chunks. Revision-scoped occurrence IDs include source/options identity and scene/node path. Names are labels, not identifiers; repeated instances remain distinct. Import transforms include the explicit glTF Y-up to GreenLens Z-up convention, scale, rotation and translation. True north stays unknown unless declared.

Mesh bounds are computed from transformed triangle vertices. Grouping occurrences have no direct geometry bounds. Triangle area and AABB dimensions are descriptive geometry quantities: they do not establish building floor area, enclosed volume, storeys, glazing properties or thermal construction performance. Source measurement of a semantic quantity requires an explicit source and method.

The importer and `verify_geometry` enforce the geometry/resource policy; `validate_manifest` checks metadata and identity consistency. Scope validation calls the latter and never claims it has read sealed geometry chunks. Services must first admit or integrity-check reference assets, and obtain analytical models from `validate_thermal_model`.

## Scope declaration and currentness

`greenlens.architectural-scope.v1` binds:

- Reference revision, geometry and canonical import-options SHA-256 identities.
- One or two selected design IDs and their exact validated model-input hashes.
- Partial-building, representative-study or whole-building scope; explicit included/excluded inventory and boundary consequences.
- Per-occurrence `mapped`, `context_only`, `excluded` or `unresolved` state. Omitted occurrences remain counted as unresolved. Mapped occurrences require targets. Context-only entries may have no simulation target, or explicitly target detached analytical shading. Excluded/unresolved entries cannot carry targets.
- Targets with design ID, semantic object ID, object kind and model hash. Accepted target kinds are zone, surface, window, overhang and detached shading. Repeated source instances can intentionally map to one abstraction, but duplicate bindings within an occurrence are rejected.

`validate_scope` accepts only exact current bindings, existing objects of the declared type and valid declarations. `assess_scope` preserves a historical declaration and reports changed source/transform, design hashes and missing occurrence/object/field references. It does not rebind a record. Reconciliation is suppressed when the declaration is stale so an old source relationship cannot label newly edited geometry. Draft scopes may retain unknown coverage, unresolved mappings and missing assumptions with explicit counts.

Whole-building scope requires a declared positive whole-building source floor-area denominator, equal included source area, an explicit whole-building review, no excluded/unresolved architecture, classification of every admitted occurrence, source mappings for every analytical zone, and a source-area reconciliation covering all zones in each design. Equality of declared source coverage uses an absolute `1e-6 m²` bookkeeping tolerance. This is not a geometry-approximation tolerance or proof that a human declaration is true. Unsupported or undemonstrated whole-building claims must remain partial/representative or blocked.

## Assumptions and measurements

Assumptions have stable IDs; study/reference/thermal links; field, value, units, source, rationale and affected scope; and one of `documented`, `measured`, `assumed`, `synthetic`, `missing`, `not_applicable`. Missing and not-applicable values are absent rather than numerical zero. Thermal field links are JSON Pointers into the actual input object and must resolve; they are never interpreted as edit commands. Concept-stage assumptions do not confer scientific qualification.

Reconciliation rows select source occurrence IDs and analytical zone IDs. Source values are explicit nullable measurements with units, source and method. Rust derives analytical values from validated thermal geometry:

| Measure | Definition and unit |
|---|---|
| Local X/Y length, height | One zone's declared dimension, m; no collection bounding-box equivalence |
| Floor area | Sum of selected zone X×Y areas, m² |
| Volume | Sum of selected zone X×Y×Z volumes, m³ |
| Exterior envelope gross area | Validated `Outdoors` surface areas, including openings, m²; excludes interzone, adiabatic and ground boundaries |
| Opening area | Sum of rectangular window width×height in selected zones, m² |
| North rotation | Building rotation normalized to [0,360), clockwise degrees; target `model:building` |

Differences are analytical minus declared source. Relative difference is `100 × difference / source`; unknown/zero denominators remain undefined. Angular difference uses the shortest signed interval [-180,180) and has no percentage. Coverage is either explicitly unknown or `100 × included source floor area / declared whole-building source floor area`. No mesh fraction or analytical subset energy is extrapolated to whole-building coverage or energy.

`greenlens.architectural-scope-assessment.v1` returns source-scope and derived report-binding hashes, current/stale relationship and reasons, measurements and counts. The report binding includes the immutable declaration, actual reference identities, selected current design identities and computed outcomes. Report presentation can bind it alongside unchanged v0.4/v0.5 data. It is not a physical simulation identity and cannot promote scientific status.

## Storage, bounds and privacy

The scope is at most 8 MiB serialized, 20,000 occurrence mappings, 64 targets per occurrence, 2,048 assumptions and 4,096 reconciliation rows. Text is bounded. Unknown schemas, duplicate bindings, dangling links, nonfinite values, incompatible units and invalid coverage denominators are rejected. The JSON schema is `schemas/architectural-scope-v0.6.schema.json`; Rust additionally enforces cross-object and identity constraints.

Retain reference manifest and normalized chunks as project-relative sealed assets. The original proprietary architectural source and GLB conversion are external by explicit storage policy; a normalized-reference evidence package is not a complete original-source archive. Save As must copy every required admitted chunk before publishing its manifest. Export preflight must account for scope and normalized assets within the shared 5,000-entry, 64 MiB-per-entry, 256 MiB-total limits, and identify exclusions. Existing private source paths do not become portable references. No imported recipe executes commands.

## Intake publication and cancellation boundary

Reference admission does not publish `project.json`. The writer first stages/seals admitted geometry externally, acquires the project writer lock and checks the expected manifest revision. Checked-directory promotion copies the immutable asset without advertising it. The existing project-open verifier then inspects the complete proposed document, including every retained static/climate/energy run, reference geometry, weather, attachments and sensitivity bindings. Energy series are decoded and their arithmetic rederived once for this candidate; sensitivity uses those exact verified records. A final content-hash fence detects evidence changed during verification.

Only after this verification succeeds does the writer recheck cancellation and the manifest revision, then atomically replace `project.json`. It returns the already verified candidate and the exact revision returned by that write; there is no fallible full reopen after publication. The prior read-only verification receipt is not attached to this new manifest: the returned candidate clears it, and a later explicit open issues a new receipt. Failed/cancelled intake leaves the old manifest and existing evidence intact. It can leave an unadvertised immutable asset; that asset is not included by project readers or exports merely because it exists on disk.

Source reads, promotion copy/hash reads and verification reads use bounded blocks, with cancellation checks at most 64 KiB apart in those loops. The borrowed import cancellation token is mirrored to the verification worker at most 50 ms apart while actual stage/run/byte events are forwarded. Copy and full candidate verification each have a 120-second budget. These are application checkpoints; an individual operating-system file operation is not a hard real-time guarantee. Immediately before atomic manifest replacement is the final cancellation boundary. A cancellation arriving after successful replacement cannot turn the accepted operation into a reported failure.

Synthetic regressions exercise corrupted retained evidence before publication, cancellation during copy/verification and at the final boundary, revision conflicts, unchanged prior manifests, bounded read interruption, and reuse of the verified candidate without misbinding the previous receipt. Their executed status belongs in the source-bound acceptance record.

## Portable named report views

The optional `report_views` collection in a scope contains at most eight `greenlens.reference-report-view.v1` definitions. Empty collections are omitted from serialization so pre-existing scope identities remain unchanged. A view binds its unique ID/title, the scope's source revision/geometry and one exact declared design model, plus orthographic eye/target/up vectors, vertical span in metres, aspect ratio and an optional axis-aligned section halfspace. Core validation rejects nonfinite/degenerate cameras, parallel up vectors, invalid spans and incompatible bindings. Perspective navigation remains display state; it is not silently converted into a report projection.

Named views are derived scope transactions and can be undone independently of physical inputs. Transient local hiding/isolation/selection is excluded from the figure declaration. `greenlens.reference-retained-orthographic.v1` uses the retained frame and clips original triangle edges to the view rectangle and optional section halfspace. It creates no filled cut faces, semantic room volume or thermal field. Vector SVG definitions, complete titles, camera/source/design identities, geometry-reduction counts and output hashes remain in `architecture-report.json`. Unknown north stays unknown. A missing bound source revision must be visibly unavailable, never drawn against a different active reference under the old binding. Historical design bindings remain explicitly historical and do not promote currentness or qualification.

## Verification scope

Original synthetic unit fixtures cover derived quantities, unknown/zero source values, duplicate/missing/wrong-kind bindings, field links, source-transform/model staleness, immutable declarations, whole-building admission conditions, scope-only derived hashes and resource limits. They do not prove a private model was decoded, a particular mapping is defensible, installed interaction works, or reports have been visually reviewed. Root-coordinated exact-source test and native records provide those separate statuses in the acceptance ledger.

## Energy report and portable export supplement

`greenlens.architectural-energy-report.v1` adds an outer canonical report dataset without editing v0.4 `energy-report.json`, v0.5 `workbench-report.json`, or any retained run. It binds the selected cases' run, record, model and physical-input identities, the base report hash, the optional workbench derived hash, retained reference revision inventory, declared scope, evaluated scope relationship and deterministic figure definitions. The assessment uses validated **selected run snapshots**, never unrelated current editor models.

When a scope refers to a retained historical reference, reports use that revision and explicitly disclose that it differs from the active reference. A missing old revision is assessed as stale against the active reference. Missing scope and unknown coverage remain visible. No source/options/model identity is silently rebound, and stale reconciliation values are suppressed.

All report families show the scope/currentness/coverage disclosure. The technical report includes reference plan and analytical abstraction; the separate appendix includes reference plan/front/right projections, both analytical models, scope inventories, mapping/readiness/assumption registers, measured reconciliation and provenance. The PDF views show up to 80 mapping/assumption rows with explicit total counts and links to the complete lossless `architecture-mappings.csv`, `architecture-assumptions.csv`, `architecture-reconciliation.csv` and `architecture-report.json`. This bounds pagination without omitting the underlying evidence.

Figures are original offline SVGs generated from admitted triangles. `greenlens.reference-orthographic-projection.v1` samples a deterministic global stride only when more than 8,000 triangles are present; captions state original/depicted counts and stride. The reduction affects presentation only. All admitted geometry remains retained, scale bars use metres, mapped/context/excluded/unresolved states use a declared legend, and true north stays unknown unless declared. The figures are reference projections, not resolved thermal fields or inferred semantic measurements. The v0.4/v0.5 template bytes stay unchanged; only an explicit architectural render permits the additional owned SVG filenames, with a separate template receipt hash.

For sensitivity, the report uses the existing policy: the first retained finalized assessment whose A10/B10 run IDs match the selected pair, including failed outcomes. Exact record and physical-input identities must also match. The supplement retains the declaration, plan/result identities, all criterion values and frozen thresholds, interruptions, limitations and receipt references. It does not choose by favorable outcome, execute additional runs, promote qualification or import unrelated session metadata. Absence of an exact assessment is stated explicitly.

An architectural energy ZIP uses `greenlens.energy-export.v0.6`. It includes **every retained admitted reference revision and chunk by default**, budgets them with the same writer/reader limits before publication, and clearly states that original proprietary sources and conversion GLB files remain external. This is a normalized-reference analysis package, not a complete original-source archive. Standalone reports contain generated figures/inventories; the portable package contains the admitted geometry. No architectural manifest is exported with silently missing required assets.

Inspection/replay recognizes v0.4/v0.5 unchanged and additionally validates the v0.6 supplement, reconstructs figures from sealed retained geometry, checks scope/report identities and verifies figure hashes before any engine replay. Imported SVG or report assertions are never executed as recipes. Integrity inspection and regeneration need neither EnergyPlus nor original source/conversion paths; native replay still requires the separately installed compatible engine.

New synthetic report tests cover escaped missing/stale disclosures, historical snapshot binding, immutable legacy report datasets, deterministic geometry figures, workbench integration, cold retained-asset reconstruction, tamper rejection, legacy package recognition and unchanged archive budgets. PDF page rendering, visual review, real private-case simulation and installed workflow remain separate acceptance items; these unit fixtures are not substitutes.
