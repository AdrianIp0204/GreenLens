# v0.6 Architectural Model Intake and Professional Case Study

Activated 2026-10-15. This bounded release extends the existing professional thermal workbench; it does not rebuild it or accept previously unobserved native workflows. The starting source is documentation `2f486ad38178acfaa1a806aecb8456db7265de6d`, application `94a80e0913579216da48ee23e3a2084a8291dc5f`. Historical specifications, failures, immutable runs and replay identities remain authoritative.

## Purpose, privacy and scientific boundary

Deliver local architectural reference intake → explicit analysis scope/mapping → reviewed inputs and assumptions → actual supported annual EnergyPlus A/B → investigation → professional reports and reproducible export. One anonymous private architectural model is a workflow, fidelity and reporting benchmark, not measured physical ground truth. Its source identity, converted geometry, screenshots, source mapping, reports, identifying metadata and machine configuration remain in private local storage outside the checkout and public artifacts. Public tests use original synthetic geometry. Never upload private data to converters or cloud services or modify the original source.

Rust/MSVC, Tauri 2, React/TypeScript/Three.js, shared Rust CLI/desktop services and separately installed engines/Typst remain. Source stays in the checkout; active builds, calculations, conversion and private evidence use local application storage. No mandatory network during normal use, Python runtime, database, general geometry kernel or plugin ABI. Native processes use bounded argument arrays and supervised Windows process trees.

Thermal scope remains 1–8 axis-aligned rectangular zones, at most two storeys, complete reciprocal full-face adjacency, supported openings/fixed shading and cooling-only single-speed DX/fan systems. Do not raise these limits or infer thermal properties from reference materials. The v0.3 qualification investigation and v0.5 Miami/Carrier protocol remain stopped. Unknown preflight-valid user cases may execute and report as Unassessed. Execution, integrity, current-input relation and exact-method scientific status remain distinct. No qualification transfer, certification claim, whole-building extrapolation, or invented sign-off.

## Gate 2: lawful inert architectural intake

Prefer self-contained GLB 2.0 exported locally using a legitimately available application. Direct proprietary-format support is optional and cannot block the neutral reader. No extracted installed DLLs, SDK redistribution, automated sign-in or purchase. Review official export documentation and actual terms; if export requires user action, identify the smallest intervention while continuing independent work.

The versioned ReferenceModel/import receipt is separate from ThermalModel. Rust owns source/conversion/importer/options identities, units/axes/origin/orientation, full hierarchy/world transforms, revision-scoped occurrence IDs (including repeated instances), bounds/counts/materials, warnings/exclusions, normalized hashes, resource measurements and simplification choices. Names are labels, never unique IDs. glTF metres and Y-up map to scientific `[x,-z,y]`; explicit user scale/orientation corrections are recorded. Preserve nested, mirrored and nonuniform transforms; verify dimensions/orientation before mapping. North/location may remain unknown.

Initial bounded static-triangle reader: 128 MiB external GLB, 8 MiB JSON, 20,000 nodes, depth 64, 40,000 meshes/accessors each, 4,096 materials, 1,024 textures, 1,000,000 instanced triangles, 80 MiB normalized geometry, 30 s processing deadline, cancellation at least each 1,024 triangles. Bound typed deserialization/allocation; reject invalid indices, unsafe/external resources, unsupported required extensions and unsupported animation/skin/morph/compressed/sparse geometry. Do not fetch URLs or execute scripts. Base colors are retained; textures/imported shading normals/cameras may be explicitly excluded from this first geometry view. Do not silently drop geometry. Declare scene selection and omitted scenes.

Normalized geometry uses sealed ≤8,192-triangle chunks; each record contains occurrence/material indices and float64 world-space coordinates. Manifest and chunks must obey the existing entry ceiling. Original proprietary source and conversion GLB remain external. Every Save As retains required admitted assets. The portable architectural analysis package includes every required admitted reference revision and chunk; standalone reports or HTML-only reports are separate explicit output choices. Preflight discloses included normalized assets and excluded original sources and checks the complete package against unchanged 5,000 entries /64 MiB per entry /256 MiB total uncompressed. An analysis-only archive that omits required admitted assets is unsupported; no partially populated architectural manifest may be exported silently. No successful export may exceed its reader's limits.

## Gate 3: source-to-analysis workbench

Extend the existing central four-view workspace. Distinguish reference, analytical and context display layers; add hierarchy search, isolate/ghost/overlay, clipping/section, measurement, linked source/zone selection and persistent named report views. Display visibility never changes simulation inclusion or scientific hashes. Retain cameras, locks, native text shortcuts, draft isolation, guarded replacement and one undo entry per accepted Rust-validated transaction.

Mappings identify source revision, coordinate transform, accepted analytical objects and mapped/context-only/excluded/unresolved status. Reimport exposes changed/stale bindings. A structured study scope declares included/excluded storeys, spaces, envelope, openings, context, systems and boundary consequences. Whole-building scope requires demonstrated supported representation. Otherwise choose a defensible partial/representative scope or stop dependent case work with a specific geometry blocker. A bounding box is not equivalent architecture. Reconcile lengths, orientation, modeled floor area, volume, envelope and opening areas with the selected source scope and quantify differences. Coverage needs a defensible denominator; otherwise it is unknown.

Use forms, not required JSON editing. Consolidate redundant object navigation, place dependency paths in compact settings/readiness, fix tree/layer overlap/scrolling, toolbar labels/grouping, focus and narrow layouts. Visual thesis: the analytical/reference view is primary; compact purposeful controls and distinct geometry treatments expose scope without decorative CAD actions. Named views, clipping and selection feedback work; no Rhino parity claim or copied assets.
