## Findings and repairs

1. The allocation test wrapper used the process working directory to resolve
   relative arguments. PowerShell `Push-Location` can leave that directory
   unchanged, causing valid caller-relative checkouts/output to resolve against
   the wrong base. A shared PowerShell provider-aware resolver now handles all
   three dependency paths and output admission, rejects non-filesystem providers,
   and retains the existing external-directory and no-overwrite guards.
2. Publishing to `main` would also run the old v0.3 Windows qualification
   workflow. Its push, pull-request and manual entry points could repeat stopped
   work. All jobs in that workflow and the four archived reference workflows are
   now inert. Definitions, recipes, thresholds and historical evidence remain.
   Current bounded energy build/energy/static-compatibility checks stay active;
   observer verification also covers main and pull requests. A source regression
   guards this separation without dispatching an experiment.
3. The latest application and allocation changes received separate read-only
   reviews. No further confirmed regression was found in the selected-object
   proposal repair, parser admission, bounded serialization, source hash fence or
   CMake changes. This targeted review is not an exhaustive proof of the entire
   v0.1-to-v0.8 codebase or optional-worker allocation closure.
