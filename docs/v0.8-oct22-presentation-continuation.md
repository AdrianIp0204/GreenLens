## Proposed versioned contract

New requests use `greenlens.design-report-content.v3` and
`greenlens.design-report-renderer/3`, for either analytical-only or explicitly
bound drawings. Existing content v1/v2, renderer identities, figure algorithms,
template/font bindings and physical/evidence identities remain available exactly.
The new document schema is `greenlens.design-report-document.v3`, paired with a
new owned template; the old template is not edited. Historical issue renderers
1–3 are outside this change. Service preparation opts into v3 only for new
content; inspection/regeneration dispatch from retained identity, never defaults.

Core adds typed criterion semantics without changing the serialized sensitivity
criterion, assessment, thresholds, measurements or pass/fail calculation. A
recognized occupied-cooling-unmet criterion is a single-run zone check only when
its quantity, id, alternative, zone, slot shape, frozen 1% limit and intentionally
absent paired values match the existing generator. Its paired cells read N/A
with that reason. Annual/peak classification requires the frozen 1%/3% limits;
changed finite or nonfinite limits are unsupported, never silently normalized.
Recognized paired annual/peak checks still require their two values. Unknown or
malformed shapes stay explicitly unsupported/missing; they cannot acquire N/A by
having null values. Existing exact-pair verification remains required.

Core adds an explicitly tagged precise value cell for the new presentation path.
Legacy `ReportCell::value` and `EnergyReportData::presentation` remain unchanged.
New savings cells retain the same finite canonical f64/unit, use fixed six decimal
places, and use deterministic scientific notation (six fractional mantissa digits)
if a nonzero value would round to zero. True positive/negative zero displays as
`0.000000`; negative nonzero values retain their sign. Non-finite values reject.
This displays the retained illustrative peak delta as `0.004401 kW`; precision
is a display policy, not uncertainty, qualification or proof of improvement.
Absolute and percentage savings, including end-use rows, share this policy;
undefined zero-baseline percentages remain typed N/A. HTML, PDF input documents,
performance JSON and CSV use the same version-dispatched presentation. A clear
policy disclosure states that display is rounded and JSON/CSV retain exact values.
