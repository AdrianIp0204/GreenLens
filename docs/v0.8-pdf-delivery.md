# v0.8 retained-PDF delivery

This is a bounded delivery repair, not a change to report calculations, qualification or issued bytes. Earlier installed candidates reported a successful shell handoff while the observed browser showed `ERR_FILE_NOT_FOUND`; the cause was not established. A separately copied exact PDF produced the same observed failure. Preserve those failures. A returned shell status cannot establish that a viewer displayed the PDF.

## Separate states and fallback

Product verification checks the selected retained product and its binding. Save Copy writes verified original bytes to an explicitly chosen destination. Reveal/Open Folder exposes the prepared file. Request Viewer asks the operating system to hand it off; successful invocation is only a request receipt. None of these statuses imply visual acceptance. The bounded inline preview uses those verified retained bytes and does not change, reissue or regenerate the report.

The current implementation uses pinned `pdfjs-dist` **6.4.299**, upstream build `d0991a0d5`. The [dependency manifest](../dependencies/pdfjs.json) binds the package archive, browser core, worker and license hashes. [Mozilla's API documentation](https://mozilla.github.io/pdf.js/api/draft/module-pdfjsLib.html) was checked against the installed version's source and types. The browser core and worker carry Apache-2.0 notices, retained in [the original license](../third-party/pdfjs/LICENSE) and [module notice](../third-party/pdfjs/NOTICE.txt). No upstream code was modified.

Only core rendering and an owned, same-origin module-worker URL are imported. No hosted viewer, PDF scripting sandbox, Node canvas binary, CMap/font/ICC/Wasm distribution or online service is shipped by this feature. npm also resolves optional Node canvas packages; those remain inventoried separately. Their native dependency SBOM includes additional libraries. This browser-only review does **not** approve redistributing those native binaries or ICU data. Production asset exclusion must be checked before packaging.

## Controls and limits

The component accepts an enumerated, backend-verified issued product as bytes, never an arbitrary file or remote URL. It copies the byte buffer before PDF.js transfers it. One dedicated worker and one visible page canvas are retained; changing issue/product or closing destroys the worker/loading task and cancels painting. Late responses cannot restore a previous selection. Page changes wait for cancelled painting before reusing the canvas. Focus stays within the preview and returns to the opener on close; Escape closes it. PDF links, scripts, attachments, forms and annotations have no action layer.

The current retained-product IPC/UI admits at most **8 MiB** for inline PDF preview. The component enforces the same **8 MiB** ceiling. Other bounds are **160 pages**, **8 million canvas pixels**, **30 seconds load**, and **15 seconds page loading/rendering**. Large pages scale down. Deadline expiry terminates the worker. The underlying PDF image-size bound may omit an oversized raster image; this is disclosed in the preview. Preview pixels do not establish complete-page fidelity, evidence integrity or scientific validity. Save Copy preserves the full original document.

`useWorkerFetch`, `useWasm`, `useSystemFonts`, XFA, image-decoder and offscreen-canvas support are disabled. A rejecting `BinaryDataFactory` prevents auxiliary-resource fetching. Embedded fonts render as paths (`disableFontFace`); no blob font permission is needed. This pinned version removed `isEvalSupported`; the false policy marker is not presented as a functioning control. The inspected core/worker contain no `eval()` or `new Function` constructor path, and no scripting sandbox is imported.

The explicit worker is a same-origin packaged module. `worker-src 'self'` is sufficient in principle; [CSP's fallback rules](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/worker-src) already fall back to the existing self-only script policy. No `blob:`, remote host, `unsafe-eval`, frame or object permission is proposed. Installed WebView2 asset loading still needs observation; a blocked worker must show failure rather than silently parsing on the UI thread.

No association or security setting was changed. This establishes the observed cause and remedy for these paths, not every possible viewer failure.

Embedded worker/CSP operation is therefore observed on this workstation, and the production asset inventory excludes optional Node canvas binaries. The cold issue and legacy issue have different hashes; their observations are not conflated. Broken/missing external associations and clean-machine installation remain unobserved. The source-checkout v0.8 acceptance ledger records exact artifacts and historical outcomes.

TypeScript passes. These tests establish component control flow only; they do not establish PDF rendering or native acceptance.
