## Main versus release findings

The C++ diff contains 39 changed files, 2,972 insertions and 322 deletions. Material changes include the pre-2014 instance GUID gate, V3/V6 format handling, zero-material parsing, geometry/material/visibility treatment and ZIP bounds. At the release pin, GUID reads depend on class schema; main gates on file version >=14. Upstream documents a prior failure that silently dropped root instances. These changes rule out treating the old release as if it contains main's fixes. Main itself remains unqualified here.

Source locations at the main pin:

- `packages/cpp/src/legacy.cpp`, entity-list handling: a root-list catch-all can stop at a failed item and return a prefix. A worker must distinguish verified format-tail handling from incomplete geometry and expose/reject uncertainty. Parser exit success is insufficient.
- `src/parser.cpp`: reads the full file into memory without a GreenLens input-size bound. `SkpFile::parse` and `build_instanced_scene` independently reparse; avoid repeatedly copying/decoding large source for counts and conversion.
- `src/core.cpp`: ZIP entry bound is 16 GiB and compression ratio limit 1,000; no GreenLens aggregate decompression budget. These are not acceptable application bounds.
- `include/openskp/observability.hpp`: synchronous progress/log callbacks exist, but no resource policy/cancellation contract. Progress alone does not interrupt decompression or long triangulation loops.
- `src/instanced_scene.cpp`: local geometry is converted from inches/Z-up to metres/glTF Y-up, `(x,y,z) -> (x,z,-y)`, with each instance matrix transformed consistently. The normal GLB intake should consume this once; applying another source-axis/unit conversion is wrong. North is independent and unknown unless declared.
- Instanced scene nodes provide names, definition names, layer strings and paths/transforms, but names are not occurrence identities. Available GUIDs differ by file era. Preserve exact node/path binding and revision; never join a metadata sidecar by label.

These are reasons for an audited bounded wrapper and small upstream patches, not a proposal to rewrite SKP parsing.

One substantive geometry, unsupported-content or containment failure stops this candidate. Ordinary compiler errors can be repaired without changing the cases/criteria; changing parser semantics after a substantive failure requires a separately recorded decision and does not erase it.

### Strictness and dependency decision

The candidate makes malformed TLV/header ranges, legacy entity-list prefix returns, unresolved edge/vertex/definition references, empty face triangulation, stalled polygon clipping and overlapping-hole approximation fatal. Texture/watermark pixels are omitted before extraction, with that omission recorded. Individual and tag visibility remain metadata; neither removes geometry. Exact occurrence paths, not names, join metadata to admitted nodes. The worker rejects unsupported version, image/billboard definitions and detected unsupported drawing primitives rather than declaring them complete.

This is a bounded strictness patch, **not a new SKP parser**. The inspected upstream reader contains best-effort metadata and entity recognition; a strict rejection of a valid fixture is a technical stopper, not a reason to restore permissive prefix success. Unknown format features and arbitrary files remain unqualified. The independent matrix must establish the supported subset before any application-intake decision. Source preparation and a successful build alone do not qualify it.

The owned minimal target intends to compile OpenSKP geometry/parser/instanced-GLB sources plus miniz and TinyGLTF/nlohmann JSON, with image decoders disabled. FlatBuffers, ThatOpen Fragments, GoogleTest, editing/writing and other exporters are not target dependencies. Retained exact notices accompany the development recipe; final compiler/linker dependency closure and runtime distribution still require the build owner's audit. A Job Object with kill-on-close and a hard committed-memory limit is required before worker startup. This is process containment, not a complete operating-system sandbox. The separate private probe remains unused and gated on all synthetic prerequisites.

### Containment stop and source-only collector checkpoint

The independent original fixtures have now been authored and audited by the official application, **not parsed by this candidate**. Before any converter execution, the native containment discriminator queried the declared 384 MiB job limit, accepted a 256 MiB commitment and rejected a subsequent 160 MiB commitment with Windows error 1455. Current private commitment and the retained pages did not grow after rejection, but the kernel-reported peak reached **438,923,264 bytes**, above the strict 384 MiB criterion. This is a retained failed peak criterion, not a passed containment claim. The optional worker build, conversion matrix, application adoption and private probe remain stopped. A source-only patch or successful fixture authoring does not resolve that failure.

`tools/openskp-worker/matrix-oracle.mjs` is an unexecuted development collector: it can prepare the fixed original/adversarial byte cases and inspect an already produced GLB against the declared oracle, but never launches a process. Process containment, exact rejection reasons and independent Rust admission remain separate requirements. Its mathematical checks include surface area, bounds, hierarchy, repeated placements, transformed bases, visibility metadata, triangle winding, hole/concavity exclusion and duplicate triangle coverage. Official authoring did not promise serialized sibling order: unique declared placements and parent relationships are checked independently, while actual metadata-to-GLB indices/paths must match exactly; names are not identity keys. The simple two cases retain their explicitly limited oracle above.

Source-only collector tests use original in-memory ZIP/TLV and GLB bytes; **12 passed, zero skipped** after correcting one test's UTF-16 alignment assumption. No actual SKP fixture preparation, candidate parser, conversion or private access occurred in this check. The previous patch-preparation tests remain separately source-only. These checks do not consume or reset the unspent conversion allowances and do not establish native reader support. Further optional execution needs a new explicit containment decision; the failed strict criterion cannot be silently relabelled.
